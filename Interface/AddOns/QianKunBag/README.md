# 乾坤背包 QianKunBag 0.1.0

这是独立新插件的首个可测试版本。目录、命令、全局命名和角色设置均独立；不依赖、覆盖或修改原 Bagshui，不读取或迁移 BagshuiData。新插件没有账户目录、银行或配置分享模块。原乾坤袋的目录与银行照常保留。

## 开始测试

1. 完全退出游戏后重新进入，在插件列表启用“乾坤背包（独立重构试用）”。新建插件目录可能需要重启客户端才能识别，单纯重新载入不能保证发现。
2. 游戏输入 `/qkb` 打开。再次输入关闭，也可用窗口“关闭”或 Escape。
3. 按键设置中有独立的“打开/关闭乾坤背包”，先绑定一个空闲按键。默认不接管 B、不改现有绑定，不自动开关原插件窗口。
4. 原乾坤袋可以保持安装和启用；若要做独立性能比较，另一次登录可只关闭旧背包插件再测。同开时旧插件及全局提示钩子仍可能产生开销，不能把整个客户端帧间隔都算作新插件耗时。

## 首版已有功能

- 当前角色的随身背包 0–4；分类分组、稳定显示排序、真实空槽和滚动。空槽提示显示实际容器，不把专业包空格伪装成通用格。
- 默认类别：任务、消耗品、装备、材料、配方、弹药、容器、灰色杂物、其他、空格。这里只按现有类型等基础字段分类，不等同于旧版任务追踪、套装、食物/饮料等复杂规则。
- 原生点击处理：使用/装备、聊天链接、试穿、拆分；拖动及放入空格调用真实袋号/槽号。合堆由原生物品操作完成。商人、邮件、拍卖及第三方点击钩子的组合需要游戏验收。
- 名称、类别或 ID 的字面搜索；未命中项变暗，保持位置与可操作性。
- Alt+右键物品选择类别，或恢复自动分类；指定按物品 ID 作用于该角色背包内的所有同 ID 物品。修改后提示位置待整理，点击“整理显示”或重新打开应用。
- 数量、SuperWoW 负数计数提供的充能、锁定灰色、品质边框、原生冷却和悬停提示。数量和品质边框放在冷却上层。
- 按角色保存归类例外、显示组顺序、列数和窗口位置；库存快照、物品资料和统计只在本次登录内保留。

首版不自动搬运或整包压缩，不替换原生背包/袋栏/银行，不接管商人等联动开关。普通 1.12 不提供负数充能时，充能仍在原生物品提示中查看；没有为了显示角标扫描全部物品提示。新增/减少徽标、数量变化历史、完整旧规则迁移、套装/当前任务上下文、复杂布局与完整编辑器尚未实现，不能把本版当成旧乾坤袋的等功能替代品。

## 分类与布局自定义

命令：

| 命令 | 用途 |
| --- | --- |
| `/qkb` | 开关窗口 |
| `/qkb sort` | 重新分类归组后的显示排序；不实际移动任何物品 |
| `/qkb categories` | 列出类别 ID 与名称 |
| `/qkb assign quest 物品ID` | 手动指定类别，优先于自动规则 |
| `/qkb auto 物品ID` | 取消此 ID 的手动指定 |
| `/qkb order consume,equipment,quest` | 调整显示组顺序，其余类别接在后面；不改变规则优先级 |
| `/qkb columns 12` | 列数 6–16 |
| `/qkb stats` | 查看缓存/控件/扫描/分类/布局/按钮更新计数及上次刷新耗时 |

鼠标带物品或拆分窗口开启时，手动整理和列数变化暂不执行。已经打开的窗口不因拾取或数量变化自动跳位；真实槽位内容照常更新，新的归组位置在整理或重开时应用。扩容需要新增格子时在游标操作结束后安全调整。

高级分类暂通过 `Categories.lua` 的纯数据声明维护；按数组顺序匹配，各条件之间是 AND，字段内的值列表是 OR。支持物品 ID 列表、排除项、类型/子类、品质、字面名称包含和最小堆叠数量。`other` 与 `empty` 为必需保留类别。配置不是 Lua 表达式执行器，未支持的规则不能直接从旧插件粘贴。

可以沿用[中文需求模板](../../../PluginHistory/Research/Bagshui分类与自定义需求模板.md)，只说明典型物品、期望分类、优先级、组位置及排序即可。先提供变更清单和验证例子，再逐步扩展常用条件；配置分享暂不做。

## 内核边界与性能检查

`Core.lua`：独立初始化、命令与事件队列；隐藏时只标记变化，不扫描、不保留 OnUpdate。`Model.lua`：按事件袋号读取，合并到下一次处理；先读取待提交变化，再更新槽位/汇总/视图；相同物品变体共享只读资料，动态数量独立；未缓存物品保留占用并最多重试 5 次，重开再次核对。缓存随当前库存淘汰，不保存历史物品全集。

`Categories.lua`：列表集合、基础字段依赖和可解释命中；数量规则按需重新分类。`View.lua`：按钮固定真实袋号/槽号；变化字段才调用对应显示设置；无变化的重复打开保留记录和布局；没有逐物品按钮 OnUpdate，只在存在事件、重试、悬停或待安全扩容时挂一个集中回调。

打开仍轻量核对所有随身容器，避免完全信任事件。发生物品内容变化且用户主动整理时，首版仍按组重建显示顺序；尚未实现完整依赖图或局部几何布局引擎。统计中的上次刷新毫秒包含该次扫描/提交/布局及计时开销，不含整个窗口 Show、原生渲染或下一帧等待；没有精确计时接口显示不可计时。计数是当前会话累计，控件计数只统计本插件物品按钮，不代表所有子控件或运行内存。

测试参考：首次 `/qkb` 后记一次 `/qkb stats`，重复关闭/打开 10 次再记一次；稳定库存应增加容器核对计数，不增加物品按钮、完整布局、分类或按钮更新。拾取/使用/拖动后检查可见数量及真实位置；Alt+右键指定后整理，确认分类与搜索一致。使用物品检查冷却与充能，测试普通包和专业包换包扩容。

受控测试：`Tools/tests/test_qiankunbag.py` 执行实际生产 Lua，使用严格字体前置条件和原生接口替身。Lua 5.1 替身与静态旧语法守卫不证明实际 Lua 5.0 客户端兼容；原生模板、滚动、层级、拆分、第三方钩子和实际耗时仍须游戏验收。

## 后续推进

先收集首版背包显示和基本操作验收，再补充用户实际需要的分类与排序能力、库存变化徽标和兼容性。更完整的分类依赖、局部分组/几何更新和资源测量分别验证。银行与离线能力待背包稳定后再设计；不通过复制旧引擎、加载账户目录或让两个插件争抢全局开关来过渡。
