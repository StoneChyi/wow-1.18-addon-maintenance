# 2026-09-29 补充11：修悬停格子报错 concat "table contains non-strings"（v1.088）

## 根因（两个，都真实存在）
1. **Lua 5.0 复用表幻影长度（主因）**：`PP_WipeTable` 只把键置 nil，但 5.0 的 `table.getn`/`table.concat` 用的是 setn 维护的**内部存储长度**——置 nil 不重置。上轮更新 tinsert 进 3 个名字、本轮清空后再插 1 个，内部长度仍记 3+，concat 扫到 nil 空洞即报错。触发点：`PallyPowerBuffButton_OnEnter` 的 4 行 `table.concat(btn.have/need/range/dead)`（现 ~1379 行）。PP_WipeTable 是 09-28 引入的复用表优化，此 bug 自那时起就存在。
2. `stats["name"]` 对未取到名字的单位（宠物等）可能为 nil → `tinsert(t, nil)` 造空洞。

## 修复（备份 backup/PallyPower.lua.20260929_fix_concat）
1. `PP_WipeTable`：清空后 `if table.setn then table.setn(t, 0) end`（5.0 归零内部长度；fengari 5.3 无 setn，guard 跳过）。
2. 新增 `local function PP_SafeConcat(tbl, sep)`：按 getn 遍历、只收 string/number 进全新表（tinsert 维护长度）再 concat；tooltip 4 行改用之。
3. 填充循环：`local uname = stats["name"] or member`（回退 unit token），4 处 tinsert 改用 uname。
- `table.concat(LastCastOn[...])` 两处不用改：每次施放都新建 `{}`，无幻影长度。
- 校验：fengari OK；sim_solo.js exit 0。**教训：本环境 Edit 工具会智能匹配，old/new_string 写错也"成功"且结果可能正确，但每次必须 Grep+Read 复核实际落点。**
