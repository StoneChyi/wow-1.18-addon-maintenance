## BetterCharacterStats — 浮动属性面板「独立显示」修复

**需求**：浮动属性面板（`BCS.PropertiesPanel`）不再受「按 C 后角色面板选中的分页」影响，独立显示自己的配置（物理/法系/治疗/猎人/混伤/防御）。

**根因**：`helper.lua` 顶部 `BCS_GET_ON_DEMAND = 1`。所有重量级取值函数
（`GetHitRating` / `GetRangedHitRating` / `GetSpellHitRating` / `GetRangedCritChance` / `GetSpellCritChance` /
`GetSpellPower` / `GetHealingPower` / `GetManaRegen` / `GetHaste` / `GetOnlyGearArmor` / `GetBlockValue`）
开头都有一段门控：只有 `BCSConfig["DropdownLeft"]` 或 `BCSConfig["DropdownRight"]`（= C 面板当前分页）
命中对应分类时才真正扫描计算，否则 `return 0`。浮动面板复用了这些函数，于是 C 面板停在别的分页时，
浮动面板的法强/命中等全变 0。

**改法（最小改动，不改门控语义）**：
1. `helper.lua`：门控条件统一改为 `if BCS_GET_ON_DEMAND and not BCS.ForceCalculate then`（共 12 处，
   含 1 处在 `GetCritChance` 的注释块内），并在 `BCS_GET_ON_DEMAND` 旁加注释说明。
2. `BCS_PropertiesPanel.lua`：在 `P:GetDisplayLines()` 与 `P:GetPropertiesForChat()` 入口
   `local prevForce = BCS.ForceCalculate; BCS.ForceCalculate = true`，出口 `BCS.ForceCalculate = prevForce` 还原。

**注意**：缓存仍走 `BCS_USE_CACHE`（1~2s），所以只是把「按 C 面板分页」这一条件解除，不会每帧重算。
副作用是浮动面板可见时会持续（约每 2s）扫描一次装备，属预期成本。

**校验**：luaparse 5.1 语法校验通过（helper.lua / BCS_PropertiesPanel.lua / BetterCharacterStats.lua / Localization.lua）。
备份：`backup/helper.lua.20260912_181338`、`backup/BCS_PropertiesPanel.lua.20260912_181338`。

## 追加：浮动面板「刷新节流」

**问题**：绕过门控后，浮动窗每 0.2 秒（`C_Timer.NewTicker`）就会重建一次全部属性内容并重排字体，
开销偏高。

**改法**（`BCS_PropertiesPanel.lua`）：
- 新增常量 `FAST_TICK = 0.2`（移速行）、`MIN_BODY_REFRESH = 1`、`MAX_BODY_REFRESH = 5`（秒）。
- 拆函数：`P:BuildBody()` 只负责重建属性内容并写入缓存；`P:GetDisplayLines()` 负责
  「按节流判定是否重建 + 每次拼接移速行」。
- 节流判定：`bodyRestLines == nil or forceNextBuild or (bodyDirty and elapsed >= MIN) or elapsed >= MAX`。
- 事件只 `P:MarkDirty()`，不直接重建；`P:RefreshNow()` 专供用户主动操作（配置按钮、/mb 命令）立即生效。
- `P:UpdateDisplay()` 优化：排版（锚点/宽度/对齐/标题颜色）只在首次或 `align` 变化时做一次
  （用 `appliedAlign` 守卫）；文本只在内容变化时 `SetText`。
- `UNIT_AURA` 只响应 `arg1 == "player"`（nil 时保守放行），避免其他单位的光环变化触发重建。
- **顺带修掉一个潜在死代码**：该客户端 `SetScript("OnEvent", ...)` 回调按香草约定**不传参**，
  而原代码写的是 `function(self, event, arg1)`。加了兼容判定：
  `if not event then event = _G.event; arg1 = _G.arg1 end`（A 约定下是空操作）。

**实测数据（fengari 离线仿真，24 项断言全通过）**：
空闲 11 次/分重建（旧逻辑 300 次/分）；每 0.5 秒一个事件的「事件风暴」下被最小间隔压到 60 次/分；
300 次 tick 里排版操作 ≤ 2 次。
脚本：`C:\Users\Administrator\.workbuddy\binaries\node\workspace\sim_bcs_panel_0912.js`
（luaparse 校验脚本 `check_bcs_0912.js`）。

**副作用**：BCS 各取值函数自身缓存 1~2 秒，所以真正「扫装备」的次数上限由它决定
（空闲约 12 次/分，事件风暴约 30 次/分）；节流主要省掉的是取值调用、字符串拼接与字体排版。

## 追加：浮动面板「自定义属性」勾选窗口

**需求**：新增第 7 个配置「自定义」+ 勾选窗口，可任意挑选要显示的属性（22 项）。

**改法**（只动 `BCS_PropertiesPanel.lua`）：
- 新增文件级 `PROPERTY_LIST`（22 项：key / label / get）与 `PRESET_KEYS`（6 个预设的 key 列表，
  与旧版硬编码顺序逐项对齐）。数组顺序 = 勾选窗口阅读顺序（行优先两列）= 悬浮窗显示顺序。
- `P:BuildBody()` 与 `P:GetPropertiesForChat()` 由「if/elseif 按 displayConfig 硬编码」改为
  `P:GetSelectedKeys()` + `P:GetPropertyText(key)` 统一循环，预设与自定义共用一条输出链路。
- 自定义勾选表存 `BCSConfig.PropertiesPanel.customProps`（key → true），首次进入自定义时
  以「切换前的预设」作为初始勾选；`customProps.speed` 控制移速行（默认开）。
- 主窗口按钮 6 → 7（宽 52），`P:SelectConfig(name)` 统一入口；`P:SyncConfigButtons()` 高亮生效项。
- 勾选窗口 `P.customFrame`（288×310，锚在主窗口右侧，右侧放不下自动改左侧），
  行/全选/清空/完成四个交互；勾选只 `MarkDirty()`（走节流），「完成」才 `RefreshNow()`。
- 命令：`/mb custom`（同时切自定义并打开窗口）。`/mb` 帮助文案同步。
- 顺带加固：`DisplayDodge/Parry/Block` 改 `pcall` 兜底并新增 `DisplayBlockValue`（自定义模式下
  任意职业都可能勾到防御类，缺 API 时回退「数据不可用」而不是整行丢失）。
- **踩坑（重要）**：`CreateCheckRow` 里最初在创建末尾调了一次 `row:Refresh()`，而该函数在
  **文件加载期**执行 —— 那时 `displayConfig` 还是 nil、`BCSConfig` 可能尚未就绪，导致勾选表被
  用「物理」兜底种子提前创建并写进 SavedVariables。已移除该加载期调用，外观统一由
  `P:RefreshCustomRows()` 在窗口显示前刷新（仿真里加了「加载期不得创建 customProps」断言防回归）。

**校验**：luaparse 5.1 通过；fengari 离线仿真 **77 项断言全通过**（含加载期副作用、种子继承、
顺序一致性、取消勾选、全选/清空、空勾选提示、兜底字符串、`/mb custom`）。
备份：`backup/BCS_PropertiesPanel.lua.20260912_182649`。

## 追加：「角色面板」开关（关闭后按 C 只显示原生的角色面板）

**需求**：浮动面板「?」旁边加一个「角色面板」开关按钮。关闭后，按 C 就是「BCS 关闭」的状态
——角色面板里不出现 BCS 的任何内容，属性只在浮动窗中显示。

**改法（2 个文件）**：

`BetterCharacterStats.lua`
- 新增 `BCS.PAPERDOLL_EVENTS`（8 个事件，与 `BCS:OnLoad` 里从 PaperDollFrame 注销的那组**完全一致**）。
- 新增 `BCS:IsCharacterPanelEnabled()`（读 `BCSConfig.PropertiesPanel.characterPanelEnabled`，默认 true）、
  `BCS:SyncCharacterPanelContent()`（只切内容归属：BCS 面板 `BetterCharacterAttributesFrame` ↔ 暴雪原生
  `CharacterAttributesFrame`）、`BCS:ApplyCharacterPanelState()`（切内容 + 注册/交还事件 + 面板开着时立即刷新）。
- 面板每次打开时同步一次：**保存 PaperDollFrame 原 OnShow 再链式 SetScript**
  （`local orig = PaperDollFrame:GetScript("OnShow")` → 调用 orig 后再 `SyncCharacterPanelContent()`）。
  这样即使暴雪自己会 show `CharacterAttributesFrame`，最终状态也一定与开关一致。
- `BCS:OnEvent()`（光环/装备变化分支前）与 `BCS:UpdateStats()` 各加一道
  `if not BCS:IsCharacterPanelEnabled() then return end` —— 关闭后连整轮装备扫描都省掉。
- 切换时若角色面板正开着，用 `PaperDollFrame:Hide(); Show()` 重新触发一次 OnShow 让数值立即刷新。

`BCS_PropertiesPanel.lua`
- `DEFAULT_CONFIG` 增 `characterPanelEnabled = true`（老用户配置无此项时自动补 true，行为不变）。
- 「?」左边新增按钮 `P.characterPanelButton`（62×16，金色=开启 / 灰色=关闭，hover 出 GameTooltip 说明）。
- `P:SetCharacterPanelEnabled(bool)` / `P:SyncCharacterPanelButton()`；`P:Init()` 里恢复状态并应用。
- 命令 `/mb panel`（别名 `charpanel` / `角色面板`）；`?` 与未知参数的帮助文案同步。

**踩坑（仿真）**：桩里 `PAPERDOLL = CreateFrame("Frame", "PaperDollFrame")` **没有赋给全局
`PaperDollFrame`**，被测代码里的相关调用全被 `pcall(function() PaperDollFrame:... end)` 静默吞掉
——断言 false 但没有任何报错，极易误判成"逻辑没写对"。修正桩（`PaperDollFrame = CreateFrame(...)`）后
全部通过，真因在桩不在代码。

**校验**：luaparse 5.1 通过；fengari 离线仿真 **105 项断言全通过**（新增 17~22 组：默认开启、
按钮关闭/开启、面板重开不回流、`/mb panel`、`Init` 恢复、不影响浮动窗）。
备份：`backup/BetterCharacterStats.lua.20260912_183904`、`backup/BCS_PropertiesPanel.lua.20260912_183904`。

### 复核：关闭状态下按 C 的 BCS 开销（用户提问，静态走查结论）

关闭状态下按 C，BCS 侧净开销 ≈ 1 次函数调用 + 2 次表查找 + 2 次可见性切换，**不触发任何装备扫描**：
1. 原生 `ToggleCharacter("PaperDollFrame")` → `PaperDollFrame:Show()`
2. 链式 OnShow 钩子 → 先跑原生 `PaperDollFrame_OnShow()`（暴雪代码）→ 再 `BCS:SyncCharacterPanelContent()`（2 次 Show/Hide）
3. 子 frame 显示级联 → `BetterCharacterAttributesFrame` 的 OnShow（XML 绑定 `BCS:OnShow()`）→ 清 `needUpdate` + `BCS:UpdateStats()` → **首行 guard 直接 return**（`BetterCharacterStats.lua:274`）

两个易误判点（已核实）：
- `PlayerStatFrameLeftDropDown_OnClick` / `RightDropDown_OnClick` 里调 `UpdatePaperdollStats` **未加 guard**，
  但关闭状态下不可达——下拉框是 `BetterCharacterAttributesFrame` 的子元素，整块被 Hide。不需要补守卫。
- 关闭后 8 个事件已**交还 PaperDollFrame**，此后原生面板自己会在属性变化时刷新（暴雪代码，非 BCS）；
  这是「恢复原生面板可用」的必然代价，不还事件则原生面板永远停在进面板那一刻的旧数值。
- BCS 无任何 `hooksecurefunc` / `HookScript` / `ToggleCharacter` 介入（已 grep 确认）。

补充证据：`CharacterAttributesFrame` / `CharacterResistanceFrame` 确实存在于该客户端
（pfUI `skins/blizzard/character.lua:209-211` 无保护地 `StripTextures` 二者），原「可能是空白」的担忧可下调。
