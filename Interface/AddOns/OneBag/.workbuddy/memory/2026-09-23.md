## 整理卡灰修复（参考 D:\Guda 对比分析）
用户反馈整理背包仍常有卡灰。通读 Guda 的 SortEngine.lua / BagFrame.lua / FrameHelpers.lua / ItemButton.lua 与 README 后定位两个根因：

1. **节奏层**：早期乌龟服保护 `defaultDelay=1.2` 在加入 sortInterval 滑条后变成死代码，实际默认 0.05s + 每轮 3 件，收尾重绘频繁撞乌龟 2-3s 的服务器锁定窗口；lockWaitDeadline 2.0s < 锁定时长；看门狗 3s≈锁定时长。Guda 同客户端节奏是 1.2s/轮（README 明说 skip-locked + 节奏是其 no stuck/grey items 设计）。
2. **显示层**：陈旧锁（>5s）分支仅凭"锁定超时"就 SetItemButtonTexture(nil)，但粘锁时物品仍在格子里（link 非 nil、贴图报空）→ 有物格子被清成无图标且无事件再纠正。Guda 靠整理期间隐藏按钮+结束整体重建躲开该窗口。

### 改动（备份 backup/20260923-1129xx）
- SortBags.lua：删死代码 defaultDelay；GetSortInterval 乌龟默认 1.2/下限 0.5（常规 0.05）；每轮预算乌龟 8/常规 3；lockWaitDeadline 2.0→3.0。
- OneBag.lua：新增 OneBag_SlotReallyEmpty(bag,slot)（贴图空且 link 也没有才算真空）；4 处 OneBag_IsSlotLockStale 分支（SafeContainerFrame_Update/UpdateBagSlots/UpdateBagSlotLocks/UpdateBagSlotLock）加 link 双重判定；profile 默认值移除 sortInterval（留 nil 让客户端默认生效）；GUI 滑条 get/set/min 同步乌龟下限 0.5、默认 1.2。
- luaparse 校验两文件通过。

**注意**：若用户存档里 sortInterval 已被手动改过，乌龟服下会被钳到 ≥0.5。

## 油类充能显示（对齐 Guda，修 SuperWoW 负数）
用户反馈：SuperWoW 下卓越法力/巫师之油数量显示为负数；Guda 能正确显示剩余次数。Guda 做法：图标右下角橙色 xN（chargesText），数据源 Nampower GetBagItemInfo 或 tooltip 扫描，BAG_UPDATE/BAG_UPDATE_COOLDOWN/PLAYER_EQUIPMENT_CHANGED + 1.2s 低频轮询补刷（涂油不改链接/堆叠数，部分流程不发 BAG_UPDATE）。

### OneBag 实现（备份 backup/20260923-120659）
- `OneBag_GetSlotCharges(bag,slot,itemCount)`：SuperWoW（SetAutoloot~=nil，与 SortBags.lua 口径一致）下 itemCount<0 → 取负得剩余充能；无 SuperWoW 降级只认 CHARGED_OILS 表（20744-20750 七种油）的正数数量。
- `OneBag_SetSlotCount(button,count,charges)` 统一数量出口：有充能→橙字 xN（并置 _hadCharges、唤醒轮询帧）；否则恢复白字堆叠数（count≤1 隐藏）。**SetItemButtonCount 不复位字色**，橙字后必须显式 SetTextColor 复位——已处理。
- 轮询帧 OneBagChargesPollFrame：~1.2s OnUpdate 只核对 _hadCharges 的可见按钮；PLAYER_EQUIPMENT_CHANGED（涂油成功改武器附魔）立即 force 一轮；无充能按钮自动 Hide 停帧。
- 4 处显示调用点全部改走统一出口：OneBag_SafeContainerFrame_Update(284) / UpdateBagSlots(3584) / UpdateBagSlotLocks(3626) / UpdateBagSlotLock(3659)。
- luaparse 两文件 OK。负数再也不直接上屏：负 itemCount 被解释为充能 → 橙字 xN；上轮中断的编辑已在本轮补齐接线。

## aux-addon 拍卖上架负数修复（同源问题）
SuperWoW 把 GetContainerItemInfo 的 count 返回负的剩余充能，污染 aux 上架链路：update_inventory_records 的 availability[充能档] = 负数 → update_item 找不到 availability[i]>0 → 滑条塌 1..1；quantity_update 的 max_stack_count 为负 → stack_count_slider 区间 (1,-5) → 值 0 → 上架按钮永久禁用。unit_vendor_price 除负数、tooltip Shift 计价也受影响。

### 改动（备份 backup/<ts>：info.lua / tabs\post\core.lua / core\tooltip.lua）
- util/info.lua `container_item`：根修——count<0 且 SetAutoloot（SuperWoW，与 OneBag/SortBags 同口径）→ charges = max(1,-count)（有 max_charges 表时，优先于 tooltip 扫描），count = 1；无 max_charges 的未知充能物则 count=1、charges=nil（走普通堆叠路径）。aux_quantity = charges or count 随之正确。
- tabs/post/core.lua `unit_vendor_price`：GetAuctionSellItemInfo 的 count<1 时按 1 处理，防单价/保管费为负。
- core/tooltip.lua `SetBagItem` 钩子：quantity<0 → 1（Shift 悬停按整瓶计价）。
- 修复后充能油在 post tab：availability[5]=1/瓶 → 滑条 1..5 → stack.start 的 find_charge_item_slot 按充能档找瓶 → post_auction 的 aux_quantity==stack_size 判定成立 → StartAuction(单价×充能数)。
- luaparse 三文件 OK。

## S_ItemTip 同源负数修复
ItemCount.lua 两处扫描循环（背包 BAG_UPDATE / 银行 InventoryCounter_UpdateBagsAndBank）：GetContainerItemInfo 负充能直接累加进 S_CountDB → tooltip 每角色/合计显示负数。修法：`if itemCount and itemCount < 0 and SetAutoloot then itemCount = -itemCount end`（合计=总剩余充能）。
ItemSocre.lua GameTooltip.SetBagItem / SetAuctionItem / SetAuctionSellItem 钩子：GameTooltip.itemCount 同口径归一（可能被外部插件读取）。
SellValue.lua 本身有 stackCount>0 防护，无需改。备份 S_ItemTip\backup\20260923-184105\。luaparse 两文件 OK。
