# Cat2 待办与讨论记录

## 调用配置卡（2026-09-16，已实现，待游戏内验证）

- 新增逻辑卡 `logic_call_configuration`，通过下拉框选择配置名称；`targetProfile` 保存字符串形式的本地稳定配置 ID。改名不影响绑定，删除后显示目标已删除。
- 子配置使用自己的被动 Apply / Validate 和参数；正常走完返回调用卡的下一张卡。子配置返回 true、校验阻止、错误或无效跳转时终止整轮。暂停调用卡不执行。
- 父子流程共用60次主执行预算，调用卡也计一步；被动预处理不计步。按活动调用栈禁止直接或间接递归，正常返回后允许再次调用同一配置。
- 按键入口统一处理待停法请求、刷新玩家信息和临时 Nampower 设置；嵌套不重复处理。每层退出均恢复父执行上下文，父治疗团队快照在子流程返回后失效重建。
- 配置导出沿用 CAT2:4 的通用参数格式，只将本卡的参数转换为 `configurationName`，不导出本地 ID、不自动打包子配置。导入先保留 `name:` 名称，再在配置加入仓库后查找唯一同名目标，绑定并提示；缺失或重名则保留待绑定名称供用户重新选择。不会因外来 ID 碰巧存在而绑定错误配置。
- 下拉参数新增 `preserveUnknownValue`：仅本卡启用，确保登录时仓库尚未恢复或目标被删除时不会丢失绑定；用户仍只能使用下拉选择。
- 施法中断策略跟随实际发起配置；记录待施法目标时同时保存配置 ID，支持延迟到达的施法事件。按键内同步事件优先使用执行中的配置。按键外的一般事件卡订阅仍沿用编辑器当前配置，事件状态仍按卡片 ID 共享，未改为所有子配置常驻订阅。
- `Tests/RunConfigurationTests.lua` 合并运行原跳转与新增调用模拟检查；覆盖上下文隔离、返回/终止、循环、共享预算、存档恢复、名称传输、异角色 ID 重绑定、缺失/重名目标与延迟治疗事件。仍需游戏内验证下拉交互、真实施法及模组兼容。

## 流程跳转规则（2026-09-12，框架已实现，待游戏内验证）

- 流程卡槽容量仍为最多 60 张卡片。
- 允许按流程编号跳转，包括向前跳转，不限制为只向后跳。
- 每轮流程最多执行 60 步；跳回后重复执行的卡片同样累计步数，跳转不重置计数。
- 达到 60 步上限后结束本轮，不再执行第 61 步，以避免跳转循环导致卡死。
- `return false` / nil 继续，`return true` 终止，`return Cat2.JumpTo(编号)` 跳转。普通表、字符串和其他旧返回值仍按 false 处理。
- 目标编号必须是当前流程内1至60的整数；无效指令作为该卡失败记录，提示并终止本轮。目标指向暂停卡或被动卡时顺次跳过。
- 主执行阶段每次调用流程卡 Execute 均计一步，包括跳转、报错及重复执行。暂停卡不计步；被动 Apply / Validate 仍提前统一处理一次，不计入60步，也不会被跳转撤销或重复处理。
- `context.currentStepIndex` 和 `context.executionStepCount` 提供当前编号与累计主执行步数；真正预算由执行器局部变量管理。现有返回统计 executedTotal 保留包含被动卡的口径。
- ExecuteCardById 的返回值也透传跳转结果，但它自身不移动流程位置；组合卡应把结果返回给执行器。内部直接调用仍属于外层流程卡的一步。
- 已调整注册器和执行器，配置存储格式不变。已新增逻辑卡“战斗中 跳转流程”（logic_flow_jump_in_combat），参数 targetIndex 为1至60的整数，默认60；卡片通过 TOC 加载。

## 动作条兼容收敛（2026-09-11，待游戏内验证）

- 保留共用角色宏载体、稳定配置 ID 与动作槽映射、配置执行和拖放机制。
- 不再覆盖 `GetActionText`：宏插件始终读取真实载体名称，原生动作按钮的配置名改在正常更新后写入其 Name 区域。自建按钮的第三方动作条可能显示载体名，需按其显示接口另行适配。
- `GetActionTexture` 仍仅对有效 Cat2 绑定返回配置图标，以保留第三方动作条的图标查询兼容；其他槽位原样转交此前接口。
- 不再由 Cat2 批量调用 `ActionButton_Update`。排队刷新只检查原生按钮，写入绑定槽位变化的名称/纹理，或撤销本插件留下的显示；不修改冷却、数量、快捷键和颜色。遵循变形条动画门禁。
- 可见 `GameTooltip:SetAction` 先调用此前接口，再追加配置说明，不清空其他插件生成的信息；其他 Tooltip 实例直接透传。
- 普通动作之间的使用/拖放交回此前接口；配置相关的拾取/放置保留返回值，能确认失败时保留原绑定或游标。无宏游标查询接口的旧客户端继续使用原有事务追踪。
- 拖配置时仅更新独立鼠标预览，不再为了预览反复编辑共享宏图标；旧载体正文迁移仍保留。
- `Tests/ProfileMacroIconTest.lua` 是脱离游戏的 Lua 模拟回归检查，不加入 TOC。覆盖宏名称冲突、提示信息保留、返回值透传、普通动作、配置改名/删除、拖放/交换/失败、翻页及变形条显示。实际第三方动作条、锁定插件和重登恢复仍需游戏内验证。

## 配置拖拽到动作条（首版已实施，待游戏内验证）

用户希望每个配置有可拖到游戏动作条上的图标，而不只是可复制的宏命令文本。

已明确的界面布局：缩窄主界面底部的宏指令复制框，在其右侧放置配置拖拽图标，保留原有复制功能。

首版行为：

- 动作条按钮直接执行绑定配置，不改变编辑器当前选中的配置。映射保存稳定配置 ID，执行时解析最新名称。
- 首次拖拽创建一个 Cat2 专用角色宏作为载体，所有配置共用；同名用户宏避让，不编辑已有用户宏。宏位不足时提示，不自动删除任何宏。
- 默认取配置内第一张未暂停的主动卡图标；空配置使用问号图标。右侧向上箭头打开选择窗，支持当前配置图标、全部图标分页及恢复自动选择。手动选择按配置 ID 保存在角色数据中。
- 指令复制框宽度136，右侧图标可见尺寸28×28、占位宽36，另有14宽的选择箭头；图标无蓝色外框。
- 无宏游标查询接口的旧客户端使用拾取/放置/清除及拖拽网格结束事件维护配置游标，不再因此拒绝拖拽。
- 实现位于 `UI/ProfileMacroIcon.lua`，动作槽绑定保存在角色数据 `ui.profileMacroIcons`；不进入配置导入导出。
- 以原生动作条为首版支持目标，第三方动作条与宏插件仍需分别实测兼容。

实现时需要检查：稳定配置 ID 绑定、配置改名和删除、动作条翻页与变形换条、拖动替换、快捷键执行、重登恢复、其他动作条/宏插件兼容，以及不同配置的运行状态隔离。

FlowEditor 拆分已实施；本次未新增 Core 文件。

## FlowEditor 模块划分

- `UI/FlowEditor.lua`：配置状态、流程实例、配置查询/切换/导入入口。
- `UI/FlowEditorCards.lua`：卡片控件及拖放交互。
- `UI/FlowEditorLists.lua`：左右列表重绘、筛选及职业预览数据。
- `UI/FlowEditorHeader.lua`：标题区、职业下拉菜单、快捷窗开关外观。
- `UI/FlowEditorWindow.lua`：主窗口布局及底部配置操作。

以上按顺序加载，内部共享状态放在 `Cat2.UI.FlowEditor`；外部仍沿用原有 `Cat2.UI` 入口。
已移除被后加载模块覆盖的旧单快捷窗实现，快捷窗统一由 `UI/ShortcutWindows.lua` 负责。
未改变配置存储格式、流程执行器或现有界面布局。
