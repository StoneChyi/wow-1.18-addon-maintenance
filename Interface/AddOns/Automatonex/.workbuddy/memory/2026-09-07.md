## Outfitter 快捷换装栏（QuickSwap.lua）：Alt+左键 加排队列表

- 用户反馈：在快捷换装栏的栏位按钮（如 OutfitterQuickSwapSlot2）上按 Alt+左键，没有把该部位加入自动排队列表。
- 根因：Alt+左键「加入/移出自动排队」的实现**只在弹出列表的网格物品按钮上**（`OutfitterQuickSwap_GridOnClick`，排队的是背包物品，用 gQS_PopupSlot 作部位名）；栏位按钮 `OutfitterQuickSwap_SlotOnClick` 没有 Alt+左键分支，左键（含 Alt）一律落到 `UseInventoryItem`（只"使用"身上饰品），所以栏位上 Alt+左键不排队。
- 修复（QuickSwap.lua，Outfitter 插件，非 Automatonex）：
  - `OutfitterQuickSwap_SlotOnClick` 在 Shift+左键 之后、RightButton 判断之前新增 `LeftButton + IsAltKeyDown` 分支：取 `GetInventoryItemLink("player", slotID)` 的当前已穿戴物品名 → `OutfitterQuickSwap_ToggleQueueItem(vSlotName, vName)` 加入/移出该部位自身队列 + `UpdateQueueMark` + 聊天框提示。语义与弹出列表 Alt+左键一致（一个是排队背包候选、一个是排队身上这件）。
  - `OutfitterQuickSwap_TooltipUpdate` 的 INVENTORY 分支补一行提示「Alt+左键 加入/移出自动排队（当前已穿戴）」。
- 备份：backup/QuickSwap.lua.20260907_222850.bak。
- ⚠️ luaparse 校验 Gotcha：QuickSwap.lua 第 364 行有 `break;`（WoW 实际 Lua 接受），luaparse 5.1 会报 ` 'end' expected near ';' ` 误报；原文件（未改）同样在此报错，属 false positive。全量校验需先把 `break;` 归一为 `break`（或临时副本 sed 替换）再 parse，确认我加的两段（约 1850 行 SlotOnClick、约 450 行 tooltip）无真实语法错误。
- ⚠️ 调用 luaparse 时的 MSYS 路径转换坑：`/d/...` 与 `D:/...` 在 Git Bash 下会被改写成 `d:\d\twmoa_1172\...`（多一段 d\）。正确做法：node 用原生 Windows 反斜杠绝对路径（`D:\twmoa_1172\...`）+ `MSYS_NO_PATHCONV=1`；`cp`/`rm` 的临时文件也走 `C:\Users\Administrator\AppData\Local\Temp\`，`rm` 用 node `fs.unlinkSync('C:/...')`（forward slash）绕开 safe-delete 把绝对路径当相对路径的 bug。
