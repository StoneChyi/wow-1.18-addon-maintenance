## pfUI 代码体检（兼容性 + 逻辑 + 性能）

用 Python 扫描器对全量 80 模块 + libs/api/env 做了 Lua 5.0 静态体检（扫描器已用构造样本验证有效）：

- **语法兼容性：干净。** `#` 长度运算符、字符串实例方法(`s:sub/find/gsub/len/format`)、`//`、`goto` 全部 0 命中。
- **缺失 API 零调用：** `GetActionInfo`、`UnitIsAFK`、`UnitIsDND` 全库 0 引用；Nampower/SuperWoW 相关 `GetUnitField`/`GetUnitGUID`/`GetNampowerVersion` 均做了 `if ... then` 或 `safeGetUnitGUID` 守卫。
- `select`/`math.mod`/`string.gfind` 在本客户端(WoW 改版 5.0.1)可用，`api.lua` 已做 `gfind=string.gmatch or string.gfind`、`mod=math.mod or mod` 两手准备。
- **性能：良好。** 核心 `unitframes.lua:OnUpdate`(1528) 单函数复用、节流 10FPS(1622)；buff/debuff OnUpdate 节流 0.2s；libdebuff 字段缓存 50ms；easteregg 11 个烟花块均做随机节流。
- **已复查逻辑正确：** player.lua 法伤/急速守卫(98 行)；castbar channel 走原生 UnitChannelInfo 兜底(148)未被 focusGuid 门控；raid.lua 宠物框顶/底对齐+中间留空自洽。
- **次要观察（非 bug）：** libunitscan.lua:91/130/153 `race = select(1, race)` 为冗余 no-op；raid.lua `PositionPetFrames` 在 lastSlot==maxraid 时 slot 会超 50 走网格续接（设计内，仅极端偏好存档情形才异常）。

结论：代码维护质量高，暂无致命兼容性/逻辑 bug。像素级布局仍需客户端实测。

## 新增「中文单位显示」缩写模式（abbrevnum）

在 `unitframes.abbrevnum` 下拉里新增两种中文数字缩写模式，与现有 k/m 模式对齐（2 位小数 + 1 位向下取整）：
- **mode "3"** = 中文 2 位小数（42500 -> 4.25万）
- **mode "4"** = 中文 1 位小数、向下取整（42500 -> 4.2万）

单位阶梯（万进制）：万=1e4、亿=1e8、兆=1e12(万亿)；低于 1e4 仍显示整数。
改动文件：`api/api.lua`(Abbreviate 函数加中文分支)、`modules/gui.lua`(abbrevnum 下拉加 3/4)、
`env/translations_zhCN.lua`(中文标签)、`env/translations_enUS.lua`(nil 占位)。
未改动默认 mode（仍为 "0" 整数），仅新增选项。

## 修复聊天框复制图标抖动 bug（聊天内容刷新快时点不到）

根因：复制按钮 `pfChatCopyButton` 挂在 `pfUI.chat.left.panelTop`（顶部频道标签条）上；
`tabmouse="1"`（profile 默认开启）的 `mouseovertab` OnUpdate 在鼠标悬停聊天框时**每节流 tick 都调 `FCF_DockUpdate()`**（无状态变化判断，原版即如此），
导致频道信息快刷新时顶部标签条持续重排抖动，按钮跟着抖、点击落空、无法复制。

两处修复：
- `modules/chat.lua` 的 `mouseovertab` OnUpdate：改为只在 hover 进入/离开的跳变边沿(`wasOverLeft/wasOverRight`)才 `Show/Hide panelTop` + 调 `FCF_DockUpdate()`，悬停期间不再每 tick 重排。
- `modules/chatcopy.lua` 的 `pfChatCopyButton`：父级从 `pfUI.chat.left.panelTop` 改为 `pfUI.chat.left`（稳定帧），锚点 `TOPRIGHT pfUI.chat.left -4`，避开 whisperproxy(`-22`)；不再随 panelTop 抖动。
仅改逻辑，未动布局外观（按钮位置视觉不变）。
