## buff 监控区上限答疑 + 名单上限 32 → 48（modules/buff.lua）
- 问题：分离 buff/debuff / 监控区有没有上限。结论分三层：数据层（aura 数组 48 槽；玩家原生 32 buff/16 debuff）、配置层（unitframes bufflimit/debufflimit）、监控按钮池。
- 监控区本体：名单本身（`#` 分隔的存档字符串）**无上限**；真上限是按钮池 `SEPBUFF_COUNT/SEPDEBUFF_COUNT`（玩家分离区）与 `TSEPBUFF_COUNT/TSEPDEBUFF_COUNT`（目标监控区），原为 32+32，槽位按**名单序号**固定（idx <= maxn 守卫，buff.lua ~L168 / ~L1153）。
- 改动（备份 `modules/buff.lua.20260923_190130.monitor-cap48.bak`）：
  1. 四个 COUNT 常量 32 → 48（= aura 数组总槽数，数据天花板）。
  2. `RefreshTargetSepBuffs` 扫描循环 `for i=1,32` → `for i=1,48`：HARMFUL 路径 libdebuff:UnitDebuff 枚举独立槽位表可覆盖 33-48；HELPFUL 路径 `libdebuff:GetBuffSlot` 有 `slot > 32 return nil` 守卫（libdebuff.lua:926），33-48 安全返回 nil。
- 安全面核实：按钮创建（`for i=1,COUNT`）、填充（`for bi=1,maxn`）、RelayoutContainer（`getn(container.buttons)`，只排 IsShown 的）、UpdateConfig 刷新循环、呼吸高亮循环（getn）全部按常量/getn 泛化，无残留硬编码 32。常量未被 buff.lua 之外引用。
- 校验：check_lua5.js SYNTAX OK；净增 0 upvalue（只改常量/循环界/注释）。
- 顺带确认：监控模式（sepbuffmonitor/sepdebuffmonitor=1）是纯复制模式，超限条目只留在原行不丢失；非监控分离模式同样有 idx<=maxn 守卫防止"隐藏了却无处显示"。
- PowerShell 工具坑：带 `$ts` 变量插值的 Copy-Item 命令静默 exit 1（无输出）；拆开单独执行或写死文件名可过。bash 工具依旧整环境损坏（date/cp/command not found）。
- backup/ 目录惯例核实：实际备份是**同目录** `.bak`（如 `api/unitframes.lua.20260918_175653.raidpet-movable.bak`），不是 backup/ 子目录——memory 里的 `backup/<file>` 记法与此不符。

## 监控区改 WA 式动态（buff.lua，同日第二改）
- 用户选定"WA 式动态"模型：名单不限长、命中即显示、按钮懒创建、位置随命中组合跳动（WA 行为）。数据层 48 槽仍是显示数天花板（单单位物理上限），但**名单序号不再占坑**（去掉 `idx <= maxn` 守卫）。
- 改动点（同文件，备份为 190130 那份 .bak 的后续叠加）：
  1. 玩家分离区登记（~L163）：去掉 `idx <= maxn`；`RefreshSepBuffs`（~L522）填充端改为遍历 `getn(GetSepList(kind))`，按钮超出初始池（SEPBUFF/SEPDEBUFF_COUNT=48 暖启动池）时 `CreateBuffButton` 懒创建 + `UpdateConfigBuffButton`，尾部多余的懒建按钮隐藏待复用。`CreateBuffButton` local 在 L186、RefreshSepBuffs 在 L522 之后 → 词法可见，可直接引用。
  2. 目标监控区：`RefreshTargetSepBuffs` 去掉 `maxn`；填充遍历 `GetTargetSepEntries(isharm, raw)` 长度；**⛔ 作用域陷阱**：`CreateTargetSepButton` 是 local（L1308）且定义在 RefreshTargetSepBuffs（L1106）之后，函数体内直接引用会解析成**全局 nil**（懒创建触发才炸）→ 新增 `pfUI.buff.EnsureTargetSepButton`（定义在 L1308 之后）经方法表运行期解引用，与 UpdateConfigTargetSepButton 同模式。
  3. `UpdateConfig` 的按钮刷新循环改为 `getn(container.buttons)` 全量 + nil 跳过（否则懒建按钮改配置后不跟尺寸）。
- 通用机制确认：RelayoutContainer 只排 IsShown 按钮 → 固定槽位模型与紧凑显示视觉等价，改模型只影响"名单序号 >池"的条目能否显示。
- 校验：check_lua5.js SYNTAX OK；净增 upvalue +2（RefreshSepBuffs→CreateBuffButton、EnsureTargetSepButton→CreateTargetSepButton，均小函数远离 32 线）。
- 实测要点：①名单 >48 条时第 49+ 条命中应出现在监控区 ②改图标尺寸后懒建按钮跟随 ③清空名单监控区全隐藏 ④监控模式下原行图标仍保留。
