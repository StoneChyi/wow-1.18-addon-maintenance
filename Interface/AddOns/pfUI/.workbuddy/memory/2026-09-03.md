## 修复 LoadMovable SetPoint Usage 报错（api/api.lua:868 + modules/loot.lua）
- 报错：`api.lua:868 Usage: pfLootFrame:SetPoint(...)`，进服即弹。
- **根因（Lua 5.0 语义层）**：`LoadMovable` 恢复位置时 `unpack(point)` 取存档锚点。拾取框「跟随鼠标」模式下锚点是 `SetPoint("TOPLEFT", nil, "BOTTOMLEFT", x, y)`（relativeTo=nil 锚屏幕），`GetPoint` 存下的表带 **nil 空洞**；Lua 5.0 的 `unpack` 默认 j=getn(t)，getn 遇空洞截断 → 只取出第 1 个值 → `SetPoint("TOPLEFT", nil, nil)` 触发 Usage 报错。
- **修复（api.lua LoadMovable）**：改 `unpack(point, 1, 5)` 显式取满 5 个值（Lua 5.0 的 unpack 支持可选 i,j，默认 j 才是 getn）；随后按类型分支 + **pcall 兜底**：c 为字符串 → 5 参形式；b 为字符串 → 4 参退化；b/c 均为数字 → `SetPoint(point,x,y)` 3 参退化（保坐标）；否则 `SetPoint(point, 0, 0)`。所有 SetPoint 都 pcall 包裹，绝不再弹 Usage。
- **辅助修复（loot.lua）**：`pfLootFrame` 创建后立即 `SetPoint("TOP", UIParent, "CENTER", 0, 0)`（两种模式都给），保证登记 movable 时总有合法锚点，屏幕锚点不会被当成初始位置保存。注：`pfUI.movables["pfLootFrame"]` 注册是此前已有人补过的。
- 验证：fengari 仿真复现旧实现报错 + 新实现 6 场景（屏幕锚点还原 nil relativeTo、普通锚点、多锚点、3 参退化保坐标、空数据、旧实现复现）全 PASS。**教训：改 api.lua 后同步更新仿真桩里的实现拷贝**（本次场景 D 因桩未同步而误报失败一次）。
- 备份 `.workbuddy/backup/api.lua.* loot.lua.*`。
