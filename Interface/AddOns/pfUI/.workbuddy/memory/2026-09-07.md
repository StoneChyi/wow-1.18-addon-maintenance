## 【重大坑】常驻 frame 调 EnableKeyboard 会吞掉全部按键（14:05 修复）
- 现象：进游戏后键盘全部失效（移动/技能/回车都无反应），鼠标完全正常。
- 根因：`pfActionMonitorKeybindListener`（上一轮为监控按键触发加的常驻帧）调了 `listener:EnableKeyboard(true)` + OnKeyDown/OnKeyUp。本客户端（SuperWoW）下该帧会抢占键盘焦点并**吞掉所有按键**，游戏绑定链收不到任何输入。afkcam 也用 EnableKeyboard 但随模式开关，GUI 里的是 EditBox——只有这个常驻帧是元凶。
- 修复：删掉 EnableKeyboard/OnKeyDown/OnKeyUp，键盘触发改为 **OnUpdate 轮询 `IsKeyDown`**（只读状态、不劫持输入）。
  - `monitorpolling = (type(IsKeyDown) == "function")` 守卫，缺失则整段降级不报错。
  - `MonitorKeyHeld(keystr)`：组合键按 "-" 拆分，ALT/CTRL/SHIFT 走 `IsAlt/Control/ShiftKeyDown()`（1.12 确定存在），末段才 `IsKeyDown(base)`——避开 IsKeyDown 修饰键名（LSHIFT 等）不确定的风险。
  - 边沿检测表 `monitorkeyheld[key]`，首次轮询必须把 nil 当 false（`local held = monitorkeyheld[key] and true or false`），否则 keyup 模式一进服就误触发一次。
  - 触发时机仍对齐 `C.bars.keydown`（1=按下沿，0=抬起沿）；聊天框/hoverbind 显示时只同步 held、不触发。
  - 惰性重建 keymap 2s 限频（UPDATE_BINDINGS 缺失兜底）。
  - **前向引用坑**：`MonitorPollKeys` 必须定义在 mon 的 `SetScript("OnUpdate")` **之前**，否则闭包里解析成全局 → nil 调用。整块键盘代码已上移到「事件驱动置脏」之前。
- 仿真：STUB 加 `KEYSTATE`/`IsKeyDown`、`C.bars.keydown`；场景 14 按键部分重写为轮询（按下/抬起沿、未绑定不触发、聊天框抑制、SHIFT-Q 组合键、监听帧不再挂键盘脚本）。约 100 断言全 PASS。备份 actionbar.lua.20260907_140655。
- **恢复方式**：改完需完全退出客户端重进（键盘废时连 /reload 都打不了；若聊天框还能打字则 /reload 即可）。
