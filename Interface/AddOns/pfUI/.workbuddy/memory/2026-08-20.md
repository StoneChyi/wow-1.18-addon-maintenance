## ⚠️ 更正 + 二次修复：黑白名单"没生效"（实际是名字匹配失效，spellID 才对）
- **更正上面"重构"条的根因**：用户实测反馈——第一版 spellID 黑名单（`GetPlayerBuffSpellId(buff.bid)`）**是生效的**，只是留空。所以 `buff.bid`（= `GetPlayerBuff` 返回值）传给 SuperWoW 的 `GetPlayerBuffID` 在你的环境里**能正确返回 spellID**；我中途改成 `PLAYER_BUFF_START_ID + buff.id` 反而是改错了参数。
- **名字版真正失效的根因**：`GetBuffName` 用 `scanner:SetPlayerBuff(buff.bid)` 读名称，但你的环境里 tooltip **取不到名字**（返回 nil），于是 AuraVisible 的名字匹配恒失败；而且当时 AuraVisible **只比名字、根本没解析数字**，所以手动填 ID 也无效——双重失效。
- **二次修复（modules/buff.lua）**：匹配改回 **spellID 优先**，名字仅作尽力兜底（不依赖它）：
  - 新增 `GetBuffId(buff)`：`pfUI.api.GetPlayerBuffSpellId(buff.bid)`（已验证可用），再兜底 `buff.fallbackSpellId`。
  - `AuraVisible`：`strsplit("#", list)` 逐项，**能转数字的按 spellID 精确比、转不了的按小写名称比**（名字兜底层）；名单空时白名单→全隐、黑名单→全显。
  - `AddToList`：存的是 spellID（点击加入），聊天回显 `名称 (ID xxxx)`；filter=="none" 时加黑名单自动切到 blacklist。
  - 删除 `GetBuffName` 里"用 spellID 兜底当名字"的错逻辑（避免名字等于数字串造成误匹配）。
- **用户迁移须知**：旧名字版测试时黑名单里存的可能是"名称字符串"，这些名字在 spellID 优先逻辑下**不会匹配**（GetBuffName 取不到名）；需清空 Blacklist 字段后，游戏内 `Shift+左键` 重新加入（存的是 ID，必中）。
- 校验：luaparse 语法通过（buff.lua）。

## ⚠️ 最终根因（"功能根本没生效"）+ 修复
- 之前反复改仍"没生效"的**真正元凶**：GUI 的 `list` 控件（`CreateConfig(...,"list")`，gui.lua 2531/2532）在用户点"+"手动添加条目时，**只会往 `C.buffs.blacklist` 写内容，不会自动把 `C.buffs.filter` 切到 "blacklist"**。结果 filter 仍是默认 "none"，`AuraVisible` 一上来 `return true`（全部显示）→ 加了黑名单却一个都不藏。Shift+左键 那条路会自动切模式，但 GUI 手动添加不会。
- 修复（modules/buff.lua）：
  - `AuraVisible` 加**智能默认**：当 `C.buffs.filter=="none"` 但 `blacklist` 非空 → 自动按 blacklist 启用；若 `whitelist` 非空 → 按 whitelist。这样无论 GUI 加还是快捷键加，"填了就生效"，不再依赖手动切 Filter Mode 下拉。
  - `AuraVisible` 匹配改用 `string.gmatch(liststr, "[^#;]+")` + 去空格，同时兼容 `#`/`;` 分隔；spellID 优先、名称尽力兜底（用户环境 GetBuffName 恒 nil，名字匹配实际是死路）。

- 结论：spellID 路径（`GetPlayerBuffSpellId(buff.bid)`，SuperWoW 提供）在用户环境**已验证可用**；唯一可靠的匹配就是 spellID。名字版彻底不可行（tooltip 取不到名）。Shift+左键 点 buff 存的是真实 ID，必中；GUI 手填必须填数字 ID 而非名称。

## ⚠️ 真·根因（"/pfhide 无效 + 模块整个失效"）：Lua 5.0 的 `#` 长度运算符
- 用户最终反馈：`/pfhide` 是"无效命令"、模块整个失效。此前所有"luaparse 语法通过"都是**假通过**。
- **真·根因**：`modules/buff.lua` 第 550 行 `local n = #container.buttons` 用了 `#` 长度运算符。WoW 1.12 跑 **Lua 5.0.1**，`#` 是 **Lua 5.1+ 才有** → 在 1.12 是**编译期语法错误** `unexpected symbol near '#'`，**整个 .lua 文件编译失败** → 模块完全不加载（所以 buff 不显示、所有 slash 命令"无效"）。
- **为什么一直没发现**：Node 的 luaparse 按 Lua 5.1+ 解析，`#` 合法，所以每次"语法通过"。真实客户端日志 `D:\twmoa_1172\Logs\FrameXML.log` 第 41 行明确报错 `Interface\AddOns\pfUI\modules\buff.lua:550: unexpected symbol near '#'`。
- **修复**：把 `#container.buttons` 换成 WoW 1.12 支持的 `getn(container.buttons)`（pfUI 各模块通用写法，buffwatch.lua/gui.lua 均用）。grep 全文件确认再无其它裸 `#` 运算符（`"[^#;]+"` 等字符串内 `#` 不受影响），无其它 5.1 特征（`//`/`goto`/`...`/`!=`）。
- **验证结论**：本次是**确定性的加载期语法错误**，修掉后模块应能正常加载（buff 显示 + `/pfhide` 生效 + 过滤 + 紧凑重排）。已记入 MEMORY.md「WoW 1.12 / Turtle Lua 5.0 兼容性坑」一节：今后改 WoW 1.12 Lua **不能用 luaparse 当验证**，必须看真实 `FrameXML.log` 的 `unexpected symbol` / `attempt to` 报错。
- 重要更正：上一条"移除 scanner 修复模块失效"是误判——scanner 移除无害，但真正让模块不加载的是 `#` 运算符，与 scanner 无关。

### ⚠️ 初版"后缀不显示"根因 + 修复（同日晚）
- 初版用 `GetItemInfo(libtooltip:GetItemLink())` 取品质。但本 Turtle 客户端背包物品链接是**短链接 `item:ID:0:0:0`**（`GetContainerItemLink` 返回），`GetItemInfo(短链接)` 返回 **nil** → `quality` 为 nil → 标签不追加。FrameXML.log 无报错（代码本身没崩，是品质取不到）。
- **修复（modules/tooltip.lua）**：改为**从名字行 `|cffRRGGBB` 颜色反推品质**——`colorblind_quality_from_text(text)` 用 `string.match(text,"|cff(%x%x%x%x%x%x)")` 取 hex，再与 `ITEM_QUALITY_COLORS[0..7]` 的 r/g/b（转 0..1）做最小距离匹配（`bestd<0.1` 命中）。颜色即品质色，不依赖任何 API、不受链接格式/缓存影响，最稳。
- 兜底：反推拿不到时，用 `libtooltip:GetItemID()`（数字 ID，正则从短链接也能提出）走 `GetItemInfo(id)` 再取品质。
- 宽度重算改用独立隐藏 FontString `colorblind_measure` 精确测量追加标签宽度（避免 `SetText` 后立即 `GetStringWidth` 可能滞后导致标签被裁切），`SetWidth(maxw+25)` 后再 `SetText`。
- 结论：色盲标记功能本身 OK，**核心坑是"用 GetItemInfo 吃短链接 → nil"**；凡在 Turtle 客户端做物品品质/信息提取，优先用名字行颜色或数字 itemID，别直接 `GetItemInfo(链接)`。

### ⚠️ 二次修复（同日晚）：字符串实例方法在本 Lua 不可用
- 报错：`tooltip.lua:57: attempt to index local 'hex' (a string value)`，但后缀实际已显示（被兜底掩盖）。
- **根因**：`colorblind_quality_from_text` 里用 `hex:sub(1,2)`（`"abc":sub(...)` 这种字符串**实例方法**），但本客户端 Lua（5.0.1）**字符串实例没有挂 `string` 元表**，对字符串做 `:` 方法调用会被当成"对字符串索引"，直接报错。
- **为什么后缀还显示**：该函数在 `Update()` 内未被 pcall 包裹，报错后未返回，调用处落到兜底分支 `GetItemInfo(数字ID)`（本客户端可用）照样补出后缀——所以是"每次悬停都抛错、但被兜底掩盖"的隐患。
- **修复**：`hex:sub(...)` → `string.sub(hex, ...)`（直接调 `string` 表函数，不碰实例索引）。其余 frame 的 `:` 方法调用（`l:IsShown()`、`GetStringWidth()` 等）作用在 table 上，不受影响。
- **新增兼容性坑（补进 MEMORY.md「WoW 1.12 / Turtle Lua 5.0 兼容性坑」）**：本客户端**不能对字符串字面量/变量用 `:` 实例方法**（如 `s:sub`/`s:find`/`s:match`/`s:gsub`），必须写成 `string.sub(s,...)` 等表函数形式；字符串实例元表缺失。注意 `string.find`/`string.gmatch`/`string.match` 等**表函数本身可用**（已验证）。
- 校验：luaparse 语法通过（tooltip.lua）。

## 性能优化（5 处，按风险从低到高逐步改）
- 按用户要求对 pfUI 做 5 处性能优化，均逐段读回验证结构正确；**最终仍需真实客户端 /reload + 看 FrameXML.log 确认**（本环境 luaparse 是 5.1 假通过，不适用 1.12）。改动均避开 `#`/`s:method`/`//` 等 5.1 语法，清表用 `getn`。
- **1. nameplates.lua 黑名单 `strlower(name)` 每帧重复**（原 597/1487/1955/1986 各算一次）：在 `HidePlate`/`OnDataChanged`/`OnShow`/`OnUpdate` 四函数各自顶部算一次 `local nameLower = name and strlower(name) or nil` 复用，减少每帧字符串重复分配与全局表查询。
- **2. tooltip.lua OnUpdate 每帧无条件 SetText**（HP 341 / MP 427）：加 `this._lastHPText`/`this._lastMPText` 缓存，仅文本变化才 `SetText`，减少重绘。HP 的 OnUpdate 无可见性守卫会每帧跑，收益更明显。
- **3. nameplates.lua `registry` 内存泄漏**：原只加入（1079）从不清理。在节流扫描块（~1087）加 `for plate in pairs(registry) do if not IsNamePlate(plate) then registry/hiddenPlates/visiblePlates[plate]=nil end`，仅剔除已销毁帧，不误删存活（含隐藏）nameplate。
- **4. api/DebuffFilter.lua OnUpdate 热路径 getglobal**：4 个 Button_OnUpdate（525/548/579/602）原每帧每按钮 `getglobal(this:GetName().."Count"/"Duration")`。改为首次懒缓存到 `this._dfcount`/`this._dfduration`，每按钮只解析一次。剩余 41 处 getglobal 在事件驱动函数（aura/config 变更），非每帧，列为可选 P2。
- **5. api/unitframes.lua aura 表复用**：原每次 `UNIT_AURA` 都 `local visible_buffs/debuffs = {}` 且每可见 aura `table.insert` 新子表（GC 压力）。改为挂 `unit._scratch_buffs`/`_scratch_debuffs` 复用外层表，并复用子表（按索引回填字段），彻底消除每次刷新的表分配。
