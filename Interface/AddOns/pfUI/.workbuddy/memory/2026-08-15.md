## 修复：local 函数前向引用报 nil（attempt to call global StartTargetSwing）
- 现象：`attempt to call global 'StartTargetSwing' (a nil value)`，报错在 `HandleAutoAttackOther` 里调用 `StartTargetSwing()` 那行。
- 根因：`HandleAutoAttackOther` 定义在 `StartTargetSwing`（local）之前，Lua 编译时把后者当成全局引用，运行时 `_G.StartTargetSwing` 为 nil。
- 修复：在 `HandleAutoAttackOther` 之前加前向声明 `local StartTargetSwing`，并把后面的 `local function StartTargetSwing()` 改成 `StartTargetSwing = function()`。
- 教训（项目约定）：在 pfUI 模块里若函数 A 要调用后面才定义的 local 函数 B，必须前向声明 `local B` 再 `B = function() ... end`，不能直接用 `local function` 且依赖顺序。

## 修复：目标右键菜单改动导致「目标框架失效」
- 现象：给 focus.lua 加菜单代码后，目标框架（target 血条）整体失效。
- 根因：`init/modules.xml` 里 `focus.lua`（第18行）排在 `target.lua`（第19行）之前；而 `pfUI.lua` 的模块加载循环 `for _, m in pairs(this.modules) do pfUI:LoadModule(m) end`（约326-330行）**没有 pcall 保护**。focus 模块函数里任何报错都会中断整个循环 → target 及其后所有模块不加载 → 目标框架失效。
- 修复：把 focus.lua 里的菜单注册整体用 `pcall(function() ... end)` 包裹，并加 nil 保护（`UnitPopupButtons`/`UnitPopupMenus`/各菜单 key/`UIDROPDOWNMENU_INIT_MENU`/`this`），确保任何客户端差异导致的报错都不会中断模块加载。
- 同时完善：菜单覆盖从仅 "TARGET" 扩到 `{"TARGET","PLAYER","PARTY","RAID_PLAYER","PET"}`（目标菜单 which 是动态的：怪物→TARGET、玩家→PLAYER/PARTY/RAID_PLAYER、宠物→PET），hook 回调不再判 `which`，只判 `button`（PF_ 前缀唯一）。
- 项目约定（重要）：pfUI 模块加载循环无 pcall，**任何模块的 RegisterModule 函数体都必须保证不抛错**，否则会连带导致其后加载的所有模块失效。往模块里加可能触碰客户端差异表（如 UnitPopupMenus）的代码时，务必 pcall + nil 保护。

## updatenotify 模块：pfUI 版本更新提醒机制（咨询解答）
- `modules/updatenotify.lua` 内置自动版本提醒：
  - 版本号编码 `major*10000+minor*100+fix`（取自 toc `## Version`），分支从 Version 字符串是否含 "experiment" 判定（exp/master）。
  - 广播：登录时向 GUILD/RAID/BATTLEGROUND 频道 `SendAddonMessage("pfUI","VERSION:版本号:分支",chan)`；进组（队伍变大）时向 RAID/BATTLEGROUND 广播。
  - 接收：`CHAT_MSG_ADDON` 且 arg1=="pfUI"，解析出更高版本则记 `pfUI_init.updateavailable`；下次登录若本地 < 该值则弹「发现新版本」提示并重置。
- 结论：**更新后无需额外操作**，正常登录/进组即自动广播；同分支、同频道（公会/团/战场）的其他 pfUI 用户下次登录会收到更新提醒。发布时只需递增 toc 的 Version 号。提醒文案硬编码在 updatenotify.lua 第 44 行。
