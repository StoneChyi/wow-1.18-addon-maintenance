## 修复：nameplates.lua 语法错误（`end' expected ... near 'else'`）+ CC 清单改 local spellIds 表（参考 EN_UnitFrames）
- 现象：`FrameXML.log` 报 `nameplates.lua:2235: 'end' expected (to close 'function' at line 1713) near 'else'`，整模块编译失败、姓名板回退原版。
- 根因①：上一轮用 Python 脚本恢复"原版内联 CC 块"时多留了一个 `end`（原 2182 行），把 `if cfg.ccenabled and isCC ...` 提前关闭，导致其后的 `elseif showDebuffsForType ...` 悬空、`OnDataChanged` 函数少一个 end、2235 的 else 挂到 function 层。**修复：删除该多余 `end`**，elseif 正确配回 `if cfg.ccenabled and isCC ...`。
- 根因②（用户指出）：之前 CC 清单用超长字符串配置 + `pfUI.ccDefaultSpells` 全局表，用户希望**参考 `D:\EN_UnitFrames\En_LoseControl.lua` 的 `local spellIds = {...}` 写法**。
- 修复（按用户要求重构）：
  - `modules/nameplates.lua`：`pfUI.ccDefaultSpells` 全局表 → **模块级 `local spellIds` 表**（116 条，与 En_LoseControl.lua 完全一致，line 28-145）；新增**全局函数** `pfUI_IsCCSpell(name) return spellIds[name] == true`（line 149-151，spellIds 只被它捕获，`OnDataChanged` 调用全局函数不占 upvalue）。
