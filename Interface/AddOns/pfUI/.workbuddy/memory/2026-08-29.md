## 解锁模式遗留宠物框架拖手问题（raid.lua）
- 现象：宠物定位已固定后，解锁模式里仍出现大量不可见的 pfRaidPet / Raid41-50 拖手。
- 根因：早期版本曾把宠物框架（UpdateMovable(f, true)）和 41-50 占位成员框注册进 pfUI.movables，unlock OnShow 会对 movables 强制 frame:Show() 并生成 dragger；旧会话拖动/保存的 pfRaidPet1..N 位置也残留进 C.position（SavedVariables）。
- 处理（modules/raid.lua，已验证 luaparse 5.1 通过）：
  1. UpdateConfig 网格循环里 `if i <= 40 then UpdateMovable(...)` —— 41-50 占位槽永不注册 movable（unlock 不再显示空拖手）；
  2. 宠物框架创建/更新循环完全不调 UpdateMovable（固定跟随团队，不可拖）；
  3. 模块加载尾部 housekeeping：`C.position["pfRaidPet" .. i] = nil`（i=1..50）清掉旧版残留的手动宠物位置，C.position 即 pfUI_config.position，登出保存后永久清除。
- 唯一注册路径确认：pfUI.movables 只能经 UpdateMovable（api.lua:906）写入；pet/占位槽已全部绕开 → /reload 后 unlock 不再出现遗留拖手。
- 若用户重进后仍见拖手：让其报拖手上文字（RaidPetN vs RaidNN）再查（可能读了旧 SavedVariables 缓存或另有模块注册）。

### 补充：真正根因（用户回报 pfRaidPet37/45 仍出现，且"有些角色有有些没有"）
- 真机制不是 movables 注册（当前代码已无宠物注册路径），而是 `api/unitframes.lua` `UpdateVisibility` 的解锁分支：`visibility = "show"` 强制显示**所有已创建的单位框**，包括：
  1. raidpet.visible="1" 的角色创建的全部 pfRaidPet1..50（无单位 → 空壳框）；
  2. pfRaid41..50 占位成员框（所有 maxraid=50 的角色都有）。
- "有些角色有，有些没有" = 是否开启 Raid-Pet 显示（逐角色配置）。
- 修复（unitframes.lua UpdateVisibility 解锁分支）：`isPlaceholder = cache_raid > 40 or strsub(fname,0,7)=="RaidPet"` 时不再强制 show，走常规可见性（无单位 → Hide）。成员 1-40 解锁强显行为不变。
- 关键排查教训：unlock 拖手只能来自 pfUI.movables（唯一写入 UpdateMovable/direct），但"解锁后看到的空框架"还可能是 UpdateVisibility 强显——两者别混淆；frame 名定位用 `fname = unit .. id`（CreateUnitFrame line 2079），fname 判 "RaidPet" 前缀即可区分宠物框（`^pfRaid(%d+)` 对 pfRaidPetN 不匹配，cache_raid=0）。
- 校验：luaparse 5.1 通过。需 /reload 验证解锁模式不再出现空宠物框/占位框。
