## 聊天自动 /who 静默拦截修补
- 用户截图反馈「开启自动查询后聊天记录中仍出现 /who 查询信息」（行格式：`21:38 洪汁1 | 玩家`）。
- 根因：1.12 中 `SetWhoToUI(1)` 只把结果列表导向好友面板，但 Blizzard 还有**另一条 chat 路径**直接写一条「<Name> | <Class>」系统消息到聊天，`SetWhoToUI(1)` 拦不住，光靠 monkey-patch `FriendsFrame_OnEvent = function() end` 是不够的。
- 修复（chat.lua）：
  1. `who_query` 新增 `silentUntil`（时间戳）+ `silentName`（被查询玩家名）两个字段。
  2. `ScanWhoName` 发起查询时打这两个标：`silentUntil = currentTime + 8` / `silentName = real`（8s 覆盖 OnUpdate 5s 超时+余量）。
  3. `WHO_LIST_UPDATE` 成功 / OnUpdate 超时两个出口都把 `silentName = nil`，停止拦截。
  4. pfUI 自己的 `AddMessage` wrapper (chat.lua:1023) 顶部按特征拦截：
     ```lua
     if who_query.silentName and GetTime() <= who_query.silentUntil then
       if string.find(text, who_query.silentName, 1, true) and string.find(text, "|", 1, true) then
         return
       end
     end
     ```
     仅在窗口期内、对「被查询玩家名 + `|`」双特征消息直接 return，不再调 HookAddMessage，自然就不会显示到聊天框。
- 风险/限制：聊天消息体如果恰好包含「<silentName> | ...」也可能被误吞（极少见）。如发现丢消息，先关 `whosearchunknown` 确认是否被该拦截误伤。
- 已同步更新 MEMORY.md「聊天自动 /who 查询」小节，把「SetWhoToUI(1) 足够」的错误描述改成本次的「必须三件套（SetWhoToUI + FriendsFrame patch + AddMessage 过滤）」才真正静默。

## 聊天自动 /who 静默拦截——计数消息「共计N个玩家」漏拦修复
- 用户二次反馈：开启自动查询后，聊天里仍出现「共计1个玩家」这类 WHO 结果计数系统消息（根目录 WTF 存档确认原始文本为 `共计1个玩家`，无空格）。
- 根因：计数消息**既不含玩家名、也无 `|` 分隔符**，靠上一轮的「silentName + `|`」双特征匹配天然漏掉。更糟的是：上一轮在 `WHO_LIST_UPDATE` 成功分支里 `silentName = nil` 提前清空，而计数消息与逐行结果是在同一波响应里稍后以 `CHAT_MSG_SYSTEM` 发出——silentName 被提前清空后，连计数过滤器（要求 silentName 非空才生效）都失效。
- 修复（chat.lua）：
  1. `AddMessage` 拦截块内新增第 (2) 类匹配：`string.find(text, "共计%s*%d+%s*个玩家")` → return（允许数字前后有空格，兼容不同客户端/语言间距）。
  2. **关键**：把 silent 窗口改为**纯时间驱动**——删除 `WHO_LIST_UPDATE` 成功分支里的 `who_query.silentName = nil`；silentName 只在 OnUpdate 超时分支清理，成功分支靠 `silentUntil = 发起到+8s` 的 GetTime() 判定自动失效，确保计数/逐行消息无论到达先后都能被拦。
- 已同步 MEMORY.md「聊天自动 /who 查询」(纠正"成功分支两处都要清 silentName"的旧说法，改为时间驱动) + 用户级技能 `wow-112-api-compat`(补充计数消息模式 + 时间窗口要点)。

## 聊天自动 /who 静默——手动查询必须照常显示
- 用户要求：手动 `/who` 查询结果照常显示，只有 pfUI 自动发起的查询才静默。之前用「发起后 8 秒整窗」判定，导致自动查询响应后那几秒内手动查询的计数消息被误吞。
- 修复：拦截激活条件由「silentName 非空 + silentUntil 整窗」改为 `pending or (GetTime()<=silentTail)`：
  - `pending` 仅 `ScanWhoName` 自动 `SendWho` 时置 true，手动 `/who` 永不置 pending → 完全不进拦截。
  - 新增 `silentTail`：`WHO_LIST_UPDATE` 成功时设 `GetTime()+1`，专吞响应后紧随的计数消息；`OnUpdate` 超时分支清 0。
  - `silentUntil`(+8s) 仅作绝对兜底上限（防 pending 卡死），实际窗口≈ pending 期(<1s)+响应后 1s 尾巴。
- 已同步 MEMORY.md + 技能 `wow-112-api-compat`(强调"手动查询不置 pending 故不受影响")。
