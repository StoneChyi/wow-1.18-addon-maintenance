## 修复「宠物不显示」（maxraid=50 方案的后续 bug）
- 根因：`api/api.lua` 的 `LoadMovable` posdata 恢复分支用了 `if a and b then SetPoint(a,b,c,d,e)`，
  其中 b = `GetPoint()` 的 relativeTo。对于「父框架相对锚定」`SetPoint(point, x, y)`（三参数，
  relativeTo 被省略→为 nil）的框架，b 为 nil → 恢复被跳过，而前面已 `ClearAllPoints()`，
  导致框架**丢失全部锚点**。
- 触发链：maxraid=50 新增的成员框架 pfRaid41..50 没有预设 position（profiles.lua 只有 1..40），
  走 LoadMovable 的 posdata 分支 → 丢锚点 → `PositionPetFrames` 里 `member:GetPoint()` 返回 nil
  → 宠物框架不被 SetPoint → 无锚点的框架即使 `Show()` 也不渲染 →「宠物不显示」。
  （第一轮外推方案不依赖成员框 41-50 的锚点，所以没暴露这个 bug。）
- 修复（api/api.lua，LoadMovable posdata 分支）：b 为 nil 时用三参数 `SetPoint(a,d,e)` 恢复父相对锚点：
  ```lua
  if a and b then
    frame:SetPoint(a,b,c,d,e)
  elseif a then
    frame:SetPoint(a,d,e)
  end
  ```
  纯增量修复（原来 b=nil 时是 no-op 导致丢锚点），不影响 b 非 nil 的现有行为。
- 校验：luaparse Lua 5.1 语法通过。需进游戏验证宠物重新显示、位置正确。

## 修复「宠物上下两半方向反了」（applyHalf 对 TOP* anchor 的下半偏移方向错误）
- 现象：36 玩家 + 2 宠物时，宠物被算到 slot 37（正确），但宠物 2 显示在 36 下方、与 36 重叠
  （用户描述「36 的下 + 37 的上」）。slot 选择没错，是**上下两半的偏移方向**错了。
- 根因：`PositionPetFrames` 的 `applyHalf` 对 **TOP* anchor（down）** 的 half=1（下半）写的是
  `py = py + pheight`。WoW 中 TOPLEFT 锚定的槽位从上往下排列（Y 越负越靠下），"下半"应向下
  移动 → `py = py - pheight`。原代码加 pheight 是向上，把宠物 2 推到了槽位 37 上方（36 底部附近）。
  （BOTTOM* anchor 的分支方向是对的，LEFT/RIGHT/CENTER 的 half=1 也一并修正为向下。）
- 修复（modules/raid.lua applyHalf）：half=1 分支 `py + pheight` → `py - pheight`；
  `py + height/2` → `py - height/2`。
- 校验：luaparse Lua 5.1 语法通过。需 /reload 验证：宠物 1 在槽位上半、宠物 2 在槽位下半，
  不再与上一个成员槽位重叠。

## 修复「切换目标时团长/助理图标延迟更新」
- 现象：目标从团长切到助理时，图标（骷髅→星星）要等约 0.5s 才变，感觉"慢慢变"。
- 根因（两层）：
  1. `RefreshIndicators` 开头 `if not unit.label or not unit.id then return end` ——
     target/focus/pet 等 id=nil 的帧被直接跳过，图标刷新（队长/助理/拾取/团队标记）
     对它们完全不生效，只能靠 OnEvent 里仅针对 raidIcon 的立即更新兜底。
     （RefreshUnit 里已有 `if not unit.id then unit.id = "" end` 处理，RefreshIndicators 缺）
  2. 队长/助理图标主要靠 OnUpdate 0.5s tick 刷新；PLAYER_TARGET_CHANGED 不触发
     立即刷新，所以骷髅残留到下一个 tick。
- 修复（api/unitframes.lua）：
  1. RefreshIndicators guard 放宽：`if not unit.label then return end`，
     unitstr 改 `unit.label .. (unit.id or "")`（与 RefreshUnit 的 id="" 处理一致）。
     副作用（符合预期）：target/focus 等帧现在也能显示队长/助理图标（UnitIsPartyLeader/
     UnitIsRaidAssistant 对任意单位有效），raidIcon 也能跟随 RAID_TARGET_UPDATE 刷新。
  2. OnEvent 的 PLAYER_TARGET_CHANGED 分支（target 帧）新增
     `this.update_indicators = true`，OnUpdate 下一帧即 RefreshIndicators，图标瞬时切换。
- 校验：luaparse Lua 5.1 语法通过。需 /reload 验证：切目标时骷髅→星星立即切换无延迟；
  target 是队长/助理时左上角显示对应图标（与团队标记 raidIcon 相互独立）。

## 修复「仅 SuperWoW 时设置焦点报 GetUnitGUID nil」（modules/focus.lua）
- 现象：仅加载 SuperWoW（无 Nampower）时，/focus 等操作触发
  `attempt to call global 'GetUnitGUID' (a nil value)`（focus.lua:157 等）。
- 根因：GetUnitGUID 是 Nampower 3.0.0+ 注入的 _G 全局，SuperWoW 不提供；
  focus.lua 是唯一**裸调 GetUnitGUID 且无 `if GetUnitGUID` 保护**的模块
  （castbar/nameplates/raid/swingtimer/superwow/unitframes 均有保护或 `or UnitGUID` 兜底）。
  注：vanilla 1.12 原生 UnitGUID 返回十进制 GUID，不能用于 TargetUnit/CastSpellByName 的
  "0x..." GUID 路径，所以无 Nampower 时整体应走 name-based。
- 修复：
  1. vanilla 分支新增 `local function GetFocusGUID(unit)`：仅当 GetUnitGUID 存在时返回
     GUID，否则返回 nil（自动落入既有的 name-based 降级分支）。
  2. 替换 5 处裸调用：/focus 无参（原 157）、/focus 带名字精确匹配（原 114）、前缀匹配
     （原 122）、/castfocus 两处（原 206/210）。
  3. 另两处 `_, guid = UnitExists("target")`（/focus 前缀匹配后、/swapfocus）改为
     GetFocusGUID——原生十进制 GUID 不能用于 GUID 路径，改后无 Nampower 正确走 name-based。
- 效果：有 Nampower 行为与原来完全一致；无 Nampower 时 /focus、/castfocus、/swapfocus
  全部 name-based（显示名字、TargetByName 切目标），不再报错。
- 校验：luaparse Lua 5.1 通过。需 /reload 在仅 SuperWoW 环境实测 /focus 不报错、
  /castfocus 走名字切换。

## GUID 回退机制统一：优先 Nampower → SuperWoW → 无模组（api.lua + libdebuff.lua）
- 需求：回退机制不统一——各模块裸名 GetUnitGUID 只解析到 _G（仅 Nampower 3.0+ 注入），
  仅 SuperWoW（有 UnitGUID）或无模组（只有 UnitExists 第二返回值）时 GUID 功能静默失效；
  且 libdebuff.lua 的 hasNampower（≥2.41）与 GetUnitGUID（≥3.0）版本不匹配，4 处无保护裸调
  （1158/1608/1616/2101）在 Nampower 2.x 时直接抛 "attempt to call global 'GetUnitGUID'"。
- 修改（api/api.lua，DLL 检测区新增）：`pfUI.api.GetUnitGUID(unit)` 三级降级——
  ① `_G.GetUnitGUID`（Nampower 优先）② `_G.UnitGUID`（SuperWoW）③ `select(2, _G.UnitExists(unit))`
  （无模组兜底，参考 D:/pfUI 原版写法）。nil/空串/"0x0000000000000000" 视为无效继续降级。
  函数体必须用 _G.xxx 显式引用（防 env 平铺自引用，见 MEMORY.md）。
  因 GetEnvironment() 把 api 平铺进模块 env，**所有模块/libs 裸名 GetUnitGUID 自动命中封装**，
  无需逐个改；无 Nampower 时 GUID 追踪/名字板过滤等由 SuperWoW/UnitExists 补齐（行为增强）。
- 修改（libs/libdebuff.lua）：4 处无保护裸调改显式 `pfUI.api.GetUnitGUID`（防御性，即使
  libdebuff 换环境也安全；`if GetUnitGUID("x")` 条件改 `if pfUI.api.GetUnitGUID then` + 判空）。
- 不改：focus.lua GetFocusGUID（顶层全局 env，有意走 name-based，GUID targeting 需 Nampower）。
- 验证：luaparse 语法通过；fengari 模拟 8 场景全过（Nampower/SuperWoW-only/无模组/nil/空串/
  全零逐级降级/单位不存在返回 nil/env 裸名命中封装一致/无自递归）；完整加载 api.lua 无报错。
  测试脚本留存 node workspace：test_guid_chain.js、test_api_load.js。需进游戏 /reload 实测。
