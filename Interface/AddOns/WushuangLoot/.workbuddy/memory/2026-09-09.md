- 新增 GUI 滑块 `WSLootSpeedSlider`(UISliderTemplate, 1~30 帧, 默认 5), 位置在 NPC 过滤输入框下方(-198~-232)。

## 修复：滑块导致插件整体加载崩溃
- 症状：小地图图标消失 + 设置界面进不去 = 整个 .lua 在加载期抛错，后续(小地图按钮/tick帧)全未执行。
- 根因：滑块用了 `speedSlider:SetOrientation("HORIZONTAL")`，而 **SetOrientation 是 WotLK(3.0) 才加的 API，WoW 1.12 客户端 Slider 无此方法**，调用即 `attempt to call method 'SetOrientation' (a nil value)`。
- 修复：删除该行。1.12 的 `UISliderTemplate` 默认即为水平滑块，无需手动设朝向。
- 教训：WoW 1.12 写 Slider 不要用 SetOrientation/GetOrientation（这些是 3.0+ API）。

## 小地图图标"仍不显示"排查
- 用 fengari 离线仿真(万能 mock 桩)确认：去掉 SetOrientation 后整个文件加载期**无错误**（"加载完成"正常打印），纹理 tubiao.tga 也存在 → 不是崩溃。
- 真因定位为**定位时机**：`UpdateMinimapButtonPosition()` 在加载期就调一次，此时 Minimap 可能未布局，`GetCenter()` 返回 (0,0)（非 nil，原 `if not mx` 拦不住）→ 按钮被放到屏幕左下角 (-56,-56) 之外，且之后只在拖动时重算 → 永久消失。
- 修复：① 初始定位挪到 `VARIABLES_LOADED`（Minimap 已布局）；② `UpdateMinimapButtonPosition` 增加 (0,0) 兜底（直接 return，留在 Minimap 默认锚点）；③ `OnDragStop` 把 `mmAngle` 存入 `WushuangLootDB.mmAngle`，重载后拖动位置不丢。
- 注：`WSLootFrame:EnableKeyboard(true)`（line~138）按用户跨项目记忆属"常驻帧开键盘"风险点，但面板默认隐藏且非本次图标问题，未动；若用户反馈开面板时无法打字再处理。

  - 已排除：toc 字节(干净)、文件属性(Archive only)、ADS(无)、文件锁(无)、SavedVariables 损坏(两个账号存档均语法 OK)、0x/#/.../select 等 5.0 语法(全无)。

## /拾取设置 无效命令 → 面包屑定位法
- FrameXML.log 实锤：其他插件 lua 加载失败记 `Error loading <路径>`、成功则静默；WushuangLoot 却记孤立 `(null)`（toc 之后、Bindings.xml 之前）→ 第三种失败状态，lua 在真实客户端从未执行（SavedVariables 13:17/13:18 有保存但无 tickInterval，证明滑块代码从未跑过）。
- 已排查排除：BOM(无)、控制字节(无)、Lua5.0 不兼容语法(#、//、goto、字符串方法调用均无)、文件锁、重复目录、编码(XyTracker 同为 UTF-8 且正常工作)。
- 手段：在关键节点插编号探针 print("WSL-1..5")（文件头/滑块前/滑块后/小地图创建后/命令注册后），用户一次 /reload 即可从聊天框看出执行停在哪。
- 同时补 ASCII 备用命令：/wsloot（执行交互）、/wsset（开设置），规避中文 slash 命令在 GBK/ANSI 客户端可能永远匹配不上的问题（SLASH_X2 别名注册）。
- 等用户回传探针结果后决定下一步：若 WSL-1 都没有 → toc/加载器层；停在 WSL-2/3 → 滑块(UISliderTemplate?)；全出 → 是命令匹配/位置问题。
