## 弹出列表支持滚轮缩放（~19:50）
- 用户反馈：`OutfitterQuickSwapItem10` 这类弹出项也要支持鼠标滚轮调整大小。
- 根因：弹出框 `OutfitterQuickSwapPopup` 的父级是 **UIParent**（当初为避开裁剪而设），不是换装栏 vFrame，所以滚轮事件冒泡不到 vFrame —— 而滚轮 handler 只挂在 frame / 标题栏 / 栏位条三处。
- 修复两处（QuickSwap.lua）：
  1. 建框处（`vPopup:Hide()` 后）加 `vPopup:EnableMouseWheel(true)` + `SetScript("OnMouseWheel", ...)` → 转调 `OutfitterQuickSwap_OnMouseWheel(arg1)`。物品按钮 `OutfitterQuickSwapItem*` 是它的子帧且未开 EnableMouseWheel → 悬停物品上滚动时事件沿父链冒泡到弹出框。
  2. `OutfitterQuickSwap_SetScale` 里补 `OutfitterQuickSwapPopup:SetScale(pScale)`：弹出框父级是 UIParent，**不继承**换装栏缩放，不单独设的话栏位放大后弹出列表仍是 100%，观感割裂（尤其"悬停弹出列表滚轮"时眼前列表不变、只有下面的栏在变）。
- **关键认知**：1.12 滚轮事件冒泡走**父链**而非逐层命中测试 —— 参照 vFrame 的接法（只开 `EnableMouseWheel`、没开 `EnableMouse`）即可证明。所以弹出框只需 `EnableMouseWheel(true)`，**不必** `EnableMouse(true)`，也就不会吞掉弹出框空白处/物品的点击。
- 时序无虞：`Initialize()` 在文件加载期建好弹出框，`LoadSettings()` 在 `PLAYER_ENTERING_WORLD` 才调 `SetScale`，此时弹出框已存在 → 存档比例能同步到。
- 校验：luaparse 全 4 文件 OK，grep 复核两处落盘（2519-2520 / 1005）。

## 校验脚本改进（luaparse 处理 Lua 5.0 的 `break;`）
- 新脚本 `.workbuddy/check_lua.js`（通用：接受命令行传文件，默认查 Outfitter 全部主 lua）。
- **旧做法有坑**：靠匹配错误信息里的 "break" 来忽略 —— 但 Lua 5.0 的 `break;` 在 luaparse 5.1 里实际报的是 `'end' expected near ';'`，**信息里根本没有 "break" 字样**，正则直接漏掉 → 误判成真语法错（Outfitter.lua:2420、QuickSwap.lua:360 都是这个，都只是 `break;`）。
- **新做法**：解析前把 `\bbreak\s*;` 统一替换成 `break` 再 parse。这样遇到 `break;` 不会中断，文件剩余部分能真正被校验到（旧做法是报错即放弃整个文件，等于没校验）。

## 双手武器与副手互斥：换装前先腾空冲突的手（~20:10）
- 用户反馈：主手装备双手武器时，换装栏换不了副手装备（点了没反应）。
- 根因：1.12 引擎不允许「双手武器 + 副手物品」共存。`OutfitterQuickSwap_DoEquip` 是裸的 `PickupContainerItem(bag,slot)` → `PickupInventoryItem(17)`，主手是双手武器时 Equip 被引擎拒绝，物品留在光标上 → 表现为"点了没反应/物品粘鼠标"。Outfitter 主逻辑（Outfitter.lua:3423 `OptimizeEquipmentChangeList`）换双手武器时会**先插入一条清空副手的 change**，换装栏缺的就是这一步。
- 修复（QuickSwap.lua，DoEquip 前新增 4 个全局函数 + DoEquip 内加一次调用）：
  - `OutfitterQuickSwap_IsTwoHandLink(pLink)`：优先 `Outfitter_GetItemInfoFromLink()` 的 `MetaSlotName=="TwoHandSlot"`（Outfitter.lua:123 `INVTYPE_2HWEAPON` 就映射成这个），兜底 `pcall(GetItemInfo, pLink)` 全参数扫描 `INVTYPE_2HWEAPON`（本客户端返回布局与标准 1.12 不同，不能硬编索引）。
  - `OutfitterQuickSwap_FindEmptyBagSlot()`：复用 Outfitter 现成的 `Outfitter_GetEmptyBagSlot()`（返回 `{BagIndex, BagSlotIndex}`，**已跳过箭袋/灵魂袋等专业包**），pcall 兜底自扫 bag 0..4。
  - `OutfitterQuickSwap_UnequipToBag(pSlotName, pMessage)`：`PickupInventoryItem(slotID)` + `PickupContainerItem(emptyBag, emptySlot)`（= Outfitter.lua:3496-3497 标准卸装写法）。空槽直接 true；槽位锁定 / 背包满 → false + 聊天提示。
  - `OutfitterQuickSwap_ResolveHandConflict(pSlotName, pBag, pSlotNum)`：装副手 + 主手双手 → 卸主手；装双手武器到主手 + 副手有物品 → 卸副手。
  - `DoEquip` 里在两次 Pickup 之前调用；返回 false 则**直接放弃不 Pickup**（否则物品粘光标），只排一次 0.75s 强制刷新。
- 覆盖路径：弹出列表点击 / 战斗队列 `ProcessQueuedSwap` / 自动排队 `ProcessAutoQueue`（后两者都走 DoEquip，自动继承）。
- 校验：luaparse 全 4 文件 OK。待用户实测：主手双手武器时换盾/副手物品应自动卸下双手武器到背包并提示"已卸下双手武器：XXX"。

## 补充：副手改走原生 UseContainerItem 路径（~20:20，用户追加反馈后）
- 用户追加信息：**主手双手武器时，背包里右键副手物品是能装备的，就 Outfitter 换装栏不行** → 说明客户端本身支持，问题在两条装备路径的差异：
  - **背包右键 = `UseContainerItem(bag, slot)`**（"使用物品"路径）：引擎内部自动卸下主手双手武器 → 成功。
  - **换装栏原写法 = `PickupContainerItem` + `PickupInventoryItem(17)`**（＝ `EquipCursorItem`，"拖拽放置"路径）：这条路径引擎**不做**自动腾手 → 直接拒绝，物品留在光标上 = 用户所见"点了没反应"。
- 因此副手**优先走原生路径**：新增 `OutfitterQuickSwap_IsOffHandOnlyItem(pBag, pSlotNum)`（盾牌/副手物品/副手武器这类"只能进副手槽"的物品：`ItemSlotName=="SecondaryHandSlot"` 或 EquipLoc ∈ SHIELD/HOLDABLE/WEAPONOFFHAND）→ DoEquip 里对该类物品直接 `UseContainerItem(bag, slot)`，与背包右键完全一致；装前若主手是双手武器，提示"主手双手武器将被卸下以装备副手"。
- **不能对所有副手候选走 UseContainerItem**：单手武器 `INVTYPE_WEAPON` 右键会被装到**主手**槽（意图是装副手，会装错手），这种情况继续走 ResolveHandConflict（手动卸双手武器）+ 指定槽 Pickup 路径。
- 覆盖路径同样是弹出列表 / 战斗队列 / 自动排队（都经 DoEquip）。校验：luaparse 全 4 文件 OK，grep 复核已落盘。
