## SetDesaturated 在弹出列表物品上会让 texture 消失（~11:10）
- 用户反馈：按 Alt 看到的弹出列表里，被屏蔽物品格子是空的棕色块（无图标），其他物品图标正常。
- 排查路径：① SetTexture 没设？GetBagItem 700 行已 SetTexture(vInfo.Texture) → 不是。② pfUI 皮肤没套？棕色块是有皮厚边框、其他有图标格子是淡边框薄环（没皮）→ 视觉上像"只有它没 texture"。③ 抓差异：被屏蔽物品与正常物品的代码路径唯一差别是 `pcall(vButton.Icon.SetDesaturated, ..., 1)`。
- **根因**：`SetDesaturated(1)` 在本客户端（1.12 + Nampower/SuperWoW）下，对普通 `Button` 的 BACKGROUND 层 Icon texture 触发了**未知的 shader 渲染异常**——texture 直接消失，只剩 pfUI backdrop 透出。OneBag 的 `SetItemButtonDesaturated` 没这个问题（专用 ItemButton API），TrinketMenu 的 `SetDesaturated(1)` 用在它自己创建的 button 上也正常——差异在我们用 pfUI 套过皮、被 SetTexCoord 裁剪过的 Icon texture 上。
- **修复**：① 改用 `vIcon:SetVertexColor(0.45, 0.45, 0.45)`（暗灰）替代 `SetDesaturated(1)`——顶点色乘法，绝对不破坏 texture 显示；正常物品强制 `SetVertexColor(1,1,1)` 归位（防 pfUI 皮肤残留旧色）；② `SetTexture` 加 fallback（nil/""→`Interface\Icons\INV_Misc_QuestionMark`），万一 GetContainerItemInfo 返回空时显示问号占位而不是 backdrop 空块。
- **泛化教训**：1.12 自定义按钮 + pfUI 皮肤的 Icon 上禁用 `SetDesaturated`；`SetVertexColor` 是永远安全的等价灰化方案。QuickSwap.lua:1346 行（Slot 按钮的 SetDesaturated(0) 反向关闭灰化）保留——它不会破坏显示。1936 行（TrinketMenu 失败灰化）暂未改但理论也有同样风险，可后续按需替换。
- luaparse OK（QuickSwap/Outfitter），grep 复核 SetDesaturated 在弹出列表渲染分支零残留。

## 角色界面 QuickSlots 弹框 pfUI 美化（~11:50）
- 用户反馈：点击纸娃娃装备槽弹出的换装条 `OutfitterQuickSlots` 27 个按钮（`OutfitterQuickSlotsItem1..27Item1`，XML 静态创建，每槽 1 个 `ContainerFrameItemButtonTemplate`）仍是 Blizzard 经典粗棕框，要求改成与 `OutfitterQuickSwapItem*` 按钮（已 pfUI 化）同款深色细边框。
- **回查发现**：pfui-skin.lua 里**没有任何** QuickSlots 皮肤代码（之前会话记忆声称做过，实际未落盘 — 教训：会话语义≠磁盘事实，**凡声称改过代码必须以文件实际内容复核**）。本次为真实首次实施。
- **实施（pfui-skin.lua, +114 行）**：
  - ① `ParseQualityColor(pLink)` 助手：`|cff(%x%x)(%x%x)(%x%x)` 正则 + Lua 5.0 逐字符 hex→0-1（`tonumber("0x..")` 不可用，5.0 无 `%` 模也用不上）。
  - ② `OutfitterQuickSlots_RefreshSkinPFUI()` 本地函数：
    - 框体：32 个 Back*（Back0/BackStart1-2/Back1-26/BackEnd/BackEnd1-2）按 `getglobal + SetTexture(nil)+Hide` 显式清（1.12 Layer 0 BACKGROUND 纹理漏清陷阱，pfUI StripTextures 在这种场景不可靠 — 已踩过，Back* 会盖在深色板上变成"PFUI 板里的小原始框"+ 吞掉按钮 click）；
    - 框体加 `pfUI.api.CreateBackdrop`（`if not qsFrame.backdrop` 幂等，CreateBackdrop 内部会重设边框色为默认，品质色放创建后单独染）；
    - 27 个按钮（用 `getglobal` 走 XML 命名，按钮自身是子 frame）：`GetNormalTexture/GetPushedTexture:SetTexture(nil)` 隐藏 Blizzard 粗框，`<Name>Border:Hide()` 隐藏 quality Border（`ContainerFrame_Update` 每次 `SetSlotToBag` 都会反复 Show/Hide 它，必须每次 OnShow 重刷），`<Name>Icon:SetAllPoints+TexCoord(0.08,0.92)` 微缩满铺，`GetHighlightTexture` 同款，`pcall(api.CreateBackdrop, btn)` 加深色细边；
    - 品质色：`parent:GetID()=bag, btn:GetID()=slot` → `GetContainerItemLink` → `|cffRRGGBB` 解析 → `btn.backdrop:SetBackdropBorderColor(r,g,b,1)`（空槽或无 link 跳过，保留 pfUI 默认色）。
  - ③ `ApplySkin` 末尾调用 `RefreshSkinPFUI()` 应用初始皮肤；
  - ④ **不**包装全局 `OutfitterQuickSlots_OnShow`（该函数当前为空，但 wrap 全局会被其他插件覆盖），改为 `qsPopup:GetScript("OnShow")` 保存原 handler + `qsPopup:SetScript("OnShow", ...)` 替换（`_pfQSOnShowWrapped` 标志防重入 — 第二次 ApplySkin 时 GetScript 会拿到自己 Set 的新函数，无标志会无限自包装）。
  - OnShow wrap 链：XML 原始 OnShow（= `OutfitterQuickSlots_OnShow()` 调用，函数体空）→ 被保存到 `_qsOrigOnShow` → 我们的新 handler 先调它，再调 `RefreshSkinPFUI()` 重刷边框色（每次 `ContainerFrame_Update` 后 `Border` 会被 Show，必须重 Hide + 重染品质色）。
- **时序**：pfui-skin.lua 在 toc 里 Outfitter.xml 之后加载，ApplySkin 在 ADDON_LOADED("Outfitter")/PLAYER_LOGIN 触发（pfUI 未就绪则等待）。ApplySkin 首次成功时：
  - 初次 RefreshSkinPFUI（bag/slot ID 默认 0，品质色跳过；Back* 残留清掉 + 框体 backdrop 建好）；
  - SetScript 包装 OnShow（用户首次点装备槽时 OnShow 触发 → 我们的 wrap 调原 OnShow + RefreshSkinPFUI，此时 bag/slot ID 已由 `SetSlotToBag` 设好 → 品质色生效）。
- 校验：luaparse 5.1 模式 OK（pfui-skin 311 行），grep 复核 `ParseQualityColor/OutfitterQuickSlots_RefreshSkinPFUI/GetScript.*OnShow/SetScript.*OnShow` 全部落盘。
- **教训（双重重申）**：① 任何"已做过的"修复先 grep 复核；② 改全局函数名易被其他插件覆盖时，用 `Frame:SetScript` 改实例 handler 是更安全的 wrap 方式。
