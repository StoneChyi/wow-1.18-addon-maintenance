# 2026-09-09

## WorldBossCooldown 击杀检测修复（世界Boss CD 追踪插件）
- **问题**：用户实测 艾索雷葛斯 / 卡扎克 击杀后插件没记录。
  - 卡扎克：模块 `Raids/Other/Kazzak.lua` 原本**没有** `module.zonename`（缺 `Outdoor Raid Bosses Zone` 标记）→ `IsWorldBoss()` 返回 false → 钩子提前 return。
  - 艾索雷葛斯：虽有标记，但依赖 Core `Victory()` → 死亡消息精确匹配链路，该链路对世界Boss很脆弱（本地化名字/标点不匹配时 `Victory` 不触发）→ `EndBossfight` 根本没被调。
- **修复**：
  1. 给 `Kazzak.lua` 补 `module.zonename = { Outdoor Raid Bosses Zone, "Blasted Lands" }`。
  2. 插件改为**自己监听 `CHAT_MSG_COMBAT_HOSTILE_DEATH`**（`OnCombatHostileDeath`），不再单纯依赖 Core 的 `Victory` 链路。
  3. `RefreshWorldBossNames()` 遍历 `BigWigs:IterateModules()`，收集世界Boss模块 `module:ToString()`（本地化名）+ 经 `Babble-Boss` 反查的英文名，做死亡日志纯文本匹配（`string.find(msg, name, 1, true)`），兼容中/英客户端。
  4. 显式 `IsKazzak()` 兜底（zhCN 名"卡扎克"/enUS"Lord Kazzak"），防止漏标。
  5. 抽出统一的 `RecordKill(name)`，并对 `Victory` 路径与死亡日志路径用 `lastRecorded` 做 10 秒去重，避免双重播报。
- **保留**：锁定提示（`CHAT_MSG_SYSTEM`）→ `[CD?]` 时间不明；`lastKill` 缓存 5 秒内锁定则撤销刚写的时间并恢复旧值。
- **验证**：luaparse 语法通过（luaVersion 5.1）；`CHAT_MSG_COMBAT_HOSTILE_DEATH` 在 BigWigs 各模块普遍使用，事件分发可靠。
- **待用户实测**：进游戏击杀 艾索雷葛斯/卡扎克，`/bwcd` 看是否出现记录与倒计时。

## 修复：乌龟服重复击杀误报 CD（WorldBossCooldown）
- **用户反馈**：乌龟服很多世界Boss可重复击杀，但一周只掉落一次；原 `RecordKill` 无条件 `kills[name]=now`，导致每次重复击杀都重置成"还有7天"，误报。
- **新语义**：冷却按"掉落"计，不是按"击杀"计。
  - `RecordKill`：若已有**在冷却期内**的记录（`existing+COOLDOWN>now`）→ 视为重复击杀，**忽略、不刷新时间**；无记录或已过期才记为本周首次掉落。
  - `OnSystemMessage`（个人锁定提示）：
    - 已有"较早"可信掉落记录（`now-existing > LOCKOUT_WINDOW=120s`）→ 保留原记录，只播报确认 `[CD] 本周已掉落，还剩X天`。
    - 否则：近期击杀被记为首次掉落则撤销（`kills[name]=nil`），标记 `[CD?]` 时间不明（本周已锁定、无掉落记录）。
  - 移除旧 `lastKill.prev` + 5秒窗口的脆弱逻辑，改为 `LOCKOUT_WINDOW=120s` 的近因判断；`lastKill` 仅存 name/time。
  - 头注释同步更新为"冷却按掉落计"的乌龟服语义。
- **验证**：luaparse 语法通过。LLM 静态推演各场景（首杀/重复击杀不刷新/过期后重记/锁定提示保留旧记录/无记录锁定标未知）均正确。
