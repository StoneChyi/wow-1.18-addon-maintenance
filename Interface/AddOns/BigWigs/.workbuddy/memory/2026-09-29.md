## 奴役恶魔两个 bug 修复（CommonAuras + VerticalBars）

- 用户实测反馈（截图）：① 释放大恶魔（地狱火/末日守卫召唤）也被显示成「奴役恶魔」条——召唤自带奴役式控制减益（纹理同为 Spell_Shadow_EnslaveDemon），宠物扫描/日志通道都会误报；② 竖行条：战斗中出现的条（如地狱火叛变 180s）脱战即消失、再进战斗也不恢复，横向条正常。
- **问题②根因**：`Plugins\VerticalBars.lua` OnEnable 注册了 `PLAYER_REGEN_ENABLED` → `WipeTimeline()` 清空整个时间轴 → 锚点隐藏；条被清了不会再回来。修：**删除该脱战清理**（条到期由 OnUpdate `endTime <= now` 自动移除，无需脱战清理；PLAYER_ENTERING_WORLD 清理保留）。教训：**长条（5min 奴役/3min 叛变）会跨战斗边界，任何"脱战清条"逻辑都会误伤**。
- **问题①修法**：复用 `CheckWarlockPet`（UNIT_PET 后 0.5s 必跑、早于奴役扫描 1s/3s，且叛变条能显示证明其可靠）——地狱火/恶魔卫士/末日守卫三个分支各打 `self.enslaveSummonAt = GetTime()` 时间戳。
- 抑制规则（扫描路径 ScanPetEnslave + 日志路径 CheckEnslaveAura 双路同规则）：
  - `freshCast`（5 秒内真施放过奴役恶魔，SPELLCAST_START 打点）**优先于抑制**——真奴役地狱火/末日守卫仍正常出条；
  - 非 freshCast 且（召唤 30 秒窗口内 或 `enslaveSummonHold` 已置位）→ 跳过广播并置 hold——hold 防止召唤 30 秒窗口过后扫描又把地狱火误报成奴役；
  - 减益消失（miss 分支）→ 清 hold。

- 注意：CheckWarlockPet 仍受 `db.profile.warlockpet` 开关门控——若用户关闭 warlockpet 而仅开 enslave，召唤抑制失效（低频 edge case，未处理）。
