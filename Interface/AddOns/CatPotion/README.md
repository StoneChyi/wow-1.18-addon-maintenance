# Cat - Potion  药剂管理

面向 WoW 1.12（Interface 11200）的独立药剂、烹饪、武器强化和毒药监视插件。当前版本为 `1.1.6`，不依赖 Cat、Cat2 或任何外部公共插件。

## 玩家使用

- 左键点击小地图图标：显示或隐藏药剂小窗。
- 右键点击小地图图标：打开独立设置。
- 每个配置拥有独立快捷小窗，最多同时打开 10 个。主界面顶部图标及配置管理中的“显示快捷小窗”控制当前配置；小窗标题旁的向下三角按钮可列出现有配置，每页最多8项，支持滚轮和翻页。菜单靠近屏幕边缘时自动调整弹出位置；屏幕空间不足时减少每页项目数，保留分页按钮。选择其他配置后，在当前小窗位置显示所选配置，并应用该配置的内容、缩放和排列；原配置小窗关闭。目标配置小窗已经开启（包括战斗中暂时隐藏）时不切换，并在聊天栏提示。切换主界面配置不会改变其他已打开小窗的内容。
- 聊天快捷条（S_ChatBar）的“药”按钮：左键打开窗口选择菜单，列出所有配置及“已开启/已关闭”状态；点击一项单独打开或关闭该配置的小窗，可分别打开多个窗口，不切换设置中的当前配置。所有窗口关闭时仍能选择。右键直接打开药剂设置。菜单支持滚轮、翻页和屏幕边缘避让；战斗中暂时隐藏的窗口仍显示为已开启，并计入最多10个窗口的上限。
- 设置中的“配置管理”可新建、重命名、删除和切换多套药剂配置；新建配置为空白，不复制当前勾选项。
- 默认配置在列表中显示 `[默认]` 标识，不可删除或重命名，但仍可修改其中的药剂勾选项。
- 点击药剂小窗中的图标或条目：尝试使用对应背包物品。
- 一键补药宏：宏内容填写 `/catpotion`，始终使用默认配置。
- 指定配置宏：使用 `/catpotion 配置名`，会切换到对应配置并执行一次一键补药；配置管理窗口提供只读命令框便于复制。
- 主设置界面右下角的只读命令框跟随当前配置；默认配置显示 `/catpotion`，其他配置显示带配置名的命令。
- 原生热键：在游戏“按键设置”的 `Cat - Potion  药剂管理` 分类中绑定“一键补药”，始终使用默认配置。
- 每次宏或热键最多尝试一个已勾选、效果缺失或即将到期的物品；再次按下处理下一个。
- “武器强化”（磨刀石、巫师油）也参与补药宏，按该配置启用的主手、副手依次涂抹；每次只处理一只手，效果充足或未装备武器时跳过。毒药仍由小窗手动使用。
- 已勾选普通药剂可在药剂小窗中右键关闭宏调用：它仍显示在小窗中并支持手动点击，但不会被 `/catpotion` 或原生热键调用。
- 药剂小窗中左键使用物品，右键切换该小窗所属配置中该普通药剂的宏调用开关。关闭时格子显示半透明红褐色底（悬停仍保持红褐色），再次右键恢复。主设置界面不提供独立的宏调用按钮；武器强化和毒药不参与此开关。
- “工程道具”收录便携式虫洞制造机：暴风城（51312）和奥格瑞玛（51313）。按角色阵营显示对应版本，包含联盟高等精灵和部落地精；“药剂全选”也只勾选适用版本。虫洞需工程学100，只能在小窗手动点击，不参与一键补药；冷却1小时、公共冷却1.5秒，实际剩余时间以客户端为准。
- 小窗自由排序：按住 Shift，用左键把一个药剂拖到另一项上，松开后交换位置。拖动时药剂图标跟随鼠标，原图标淡化，源条目为金色、目标条目为绿色；松开在窗外取消。跟随图标适配界面及小窗缩放，松手或关闭窗口后消失。顺序按配置保存，重新登录或重载后保留，横向、纵向及最小化模式均可使用；主手、副手条目可分别排序。“锁定小窗位置”只锁窗口移动。配置管理中的“恢复默认顺序”可重置当前配置。排序不改变补药宏的优先级；取消勾选再恢复会保留已保存的相对顺序，新勾选条目追加到自定义顺序末尾。
- “生存药剂”包含强效奥术、暗影、自然、火焰和冰霜防护药水；新增物品默认不勾选，勾选后沿用普通药剂的倒计时、冷却、点击使用和宏调用开关。
- 新增“功能药水”“恢复物品”“常用炸药”“工程道具”四类，共 55 项。包含迅捷、献祭之油、有限无敌、乌龟服加速药水、魂能之速、自由/活力行动、强怒、石盾、隐形、净化、大红大蓝、草药茶、菊花茶、符文、治疗石，以及常用手雷、工兵炸药、假人和背包直接使用的工程道具。
- 新增项目默认不勾选；勾选后默认仅显示。功能药水中有玩家 Buff 的短效物品，可在小窗右键开启一键补药；它们仅在 Buff 消失后补充，不受长期药剂的四分钟预警影响。无玩家 Buff 的恢复品、炸药和工程道具始终由左键手动使用，避免错误消耗和抢占补药顺序。
- “恢复物品”新增魔法橘子（83004）及沙漏（19183，解除龙血之痛：青铜）。沿用背包数量、手动使用、自定义排序和配置保存；两者均不参与补药宏。魔法橘子需脱战坐下进食，使用物品的食物共享冷却为1秒；沙漏没有自身、类别或公共冷却，可在战斗中使用。图标和参数按当前客户端缓存核对，实际冷却优先读取客户端。
- 不收录需要装备的工程饰品、头盔和靴子。投掷炸药仍按游戏原有流程手动选取地面位置；魂能之速对自己使用并恢复原目标。
- 设置物品项悬停可查看完整名称、用途、自身冷却及类别共享冷却。图标、物品 ID、Buff 名称和冷却参数以本客户端物品缓存和补丁数据核对，实际剩余时间读取客户端接口；物品按 ID 匹配可兼容背包中的不同本地化名称。
- “剩余时间警告”既控制倒计时颜色，也是 `/catpotion` 提前补药的时间阈值。
- 武器强化和毒药在设置中分别选择主手或副手，不纳入一键补药；小窗按槽位独立显示，点击后尝试自动应用到对应武器。
- “毒药”分类排在“武器强化”之后，依次包含“速效毒药 VI”“溶解毒药 II”“致命毒药 V”“致命毒药 IV”“腐蚀毒药 II”“腐蚀毒药”“麻痹毒药 III”“致伤毒药”和“致残毒药”，默认不启用主/副手。背包按完整物品名匹配；致伤毒药和致残毒药当前收录不带等级后缀的物品。毒药与磨刀石、巫师油共用对应武器的临时附魔槽，涂抹时可能替换该手原有强化。
- 毒药图标左上角显示该手武器上毒药的剩余使用次数：小于 20 时数字为红色，20 及以上为金黄色；右下角仍是背包数量。没有可读次数、毒药已失效或类型不匹配时不显示左上角数字。这里不是目标身上的毒药 Debuff 叠层。
- 设置界面中若同时勾选冲突关系表中的药剂，选择框左侧会显示红色“！”；关系表以桌面新版 Cat 为基础并包含 CatPotion 后续补充，它只作提醒，不会自动取消选项，也不影响小窗点击或一键补药。

## 文件职责

- `Core.lua`：唯一数据源；包含物品、纹理、说明、数据库、背包/Buff/附魔缓存和使用入口。
- `Window.lua`：可点击药剂小窗、横纵排列、状态优先级、事件合并、跨帧安全重排与每秒倒计时刷新。
- `Settings.lua`：独立设置界面、三列选择列表、小窗布局参数和只读宏提示框。
- `MinimapButton.lua`：小地图入口及基于角度的拖动位置保存。
- `Bindings.xml`：把原生“一键补药”热键绑定到 `CatPotionUseCommand()`。
- `CatPotion.toc`：加载顺序必须保持 `Core.lua` 在最前、`Bindings.xml` 在功能代码之后。

## 2026-08-17 多配置维护说明

### 数据模型与迁移

- `CatPotionDB` 是每角色数据库。多配置入口为 `profiles`、`profileOrder`、`activeProfileId`、`defaultProfileId` 和 `nextProfileId`。
- 每个配置保存 `selected`（普通药剂）、`macroExcluded`（仅显示、不参与宏的普通药剂）、`weaponSlots`（武器强化槽位）、`windowOrder`（小窗自定义条目顺序），以及 `scale`、`layout`、`layoutLimit`、`locked`、`showMessages`、`warningMinutes`。缩放、排列方向和每行或列项目数在配置管理中设置，随配置切换；已有配置首次继承旧全局值，新配置默认缩放 0.8、横向优先、每行 2 项。
- 旧版顶层 `CatPotionDB.selected` 会在首次加载时迁移到 ID 为 `1` 的“默认配置”，随后删除旧字段。
- 旧版配置中按普通物品勾选的武器强化会迁移为主手选择，避免更新后条目消失。
- 默认配置由 `defaultProfileId` 判断，不要依赖配置名称。它可以修改药剂内容，但数据层和界面层都禁止删除、重命名。
- 新建配置必须为空白，不能复制当前配置；至少始终保留一套配置。

配置内部结构示意：

```lua
profiles[profileId] = {
    id = profileId,
    name = "物理输出",
    selected = { mongoose = 1 },
    macroExcluded = { mongoose = 1 },
    weaponSlots = {
        elementalStone = { main = 1, off = 1 }
    }
}
```

### 命令语义

- `/catpotion` 与 `Bindings.xml` 原生热键固定使用默认配置，不受设置界面当前配置影响。
- `/catpotion 配置名` 会切换到同名配置并执行一次补药；配置名按完整字符串精确匹配。
- 每次硬件输入最多尝试一个药剂或一只手的武器强化；毒药、即时恢复品和炸药不进入一键补药候选。
- `macroExcluded` 中标记的普通药剂由药剂小窗右键控制；它们仍参与小窗显示，但不进入一键补药候选。
- 主设置窗和配置管理窗共用 `GetProfileCommand()` 生成只读宏文本：默认配置只显示 `/catpotion`，其他配置显示 `/catpotion 配置名`。

### 配置界面

- 小窗通过 `GetProfileWindowEntries(profile)` 合并自定义顺序、勾选状态和阵营限制；普通条目 ID 为物品 key，武器类条目 ID 附加 `:16` 或 `:17`。拖动只保存 `windowOrder` 并请求下一帧重排，禁止在鼠标回调中直接修改尺寸或锚点。Shift 点击与拖动后的松手点击不会使用物品或切换宏；窗口隐藏时取消拖动。补药宏仍读取原始 `SettingsOrderItems`。
- 主设置窗右上角显示当前配置并提供“配置管理”入口；管理窗打开时 `mainWindowDim` 遮暗并拦截主窗操作。
- 药剂小窗的配置切换小三角在每行两项、单项、纵向排列和最小化模式均保留。标题栏按窗口实际宽度安排按钮；窄图标窗只显示配置切换和关闭，宽度足够时再显示设置按钮，标题为按钮预留空间。
- 配置选择菜单按屏幕边界及实际缩放定位：底部空间不足时向上展开，左右和顶部越界时移回屏幕内。每次翻页或滚动后重新定位；极小屏幕自动减少每页项目数，必要时只缩小菜单，确保全部配置仍可访问。此定位只调整菜单，不修改主小窗拖动或位置保存逻辑。
- 快捷条通过 `TogglePotionWindowPicker(anchor)` 打开独立于药剂小窗的选择菜单；与小窗三角菜单共用 `CreateProfileMenu` 的分页和屏幕定位。快捷条选择只调用 `SetProfileWindowVisible`，小窗三角选择继续调用 `SwitchPotionWindowProfile`。两种菜单互斥显示，快捷条右键调用 `ShowSettings`；小地图入口保持原有设置开关行为。
- 管理窗采用 Cat2 风格：左侧配置列表，右侧“新建、删除、重命名”同排按钮与只读宏框。
- 默认配置在列表中用独立金色 `[默认]` 标签标识；选中时删除、重命名按钮变暗，点击仍会由逻辑层拒绝。
- 普通物品继续使用三列复选框。武器强化和毒药使用两列宽条目，每项分别提供“主手”和“副手”独立开关。
- “药剂全选”只选择普通物品，不自动开启武器强化或毒药；“全部清除”同时清空普通药剂、宏排除标记和武器槽位。

### 短效物品与共享冷却

- `GetCooldownInfo(itemName)` 返回剩余秒数、`item/shared/gcd` 类型及客户端的不可用状态；`GetCooldownRemaining` 保留原调用方式。真实短冷却不再被统一忽略，冷却末尾不足半秒仍会阻止使用。
- 原有药剂也补充已知冷却类别。工兵自身冷却 300 秒，只给其他炸药传播 60 秒；普通药水共享 120 秒；献祭之油属于 3 秒药剂类别，不并入 120 秒药水类别；诺达纳尔草药茶与符文共享 120 秒。魂能之速自身 60 秒，技能类别锁为 10 秒，猎人技能造成的更长锁由客户端接口读取。
- 技能公共冷却与物品类别共享冷却分开。只有背包短锁与无自身冷却的已学技能的开始时间和持续时间完全一致时，才把它识别为技能 GCD；无 GCD 的药水忽略这种覆盖，受 GCD 限制的物品保留客户端实际时长。宏的 0.2 秒防重复间隔不代替 GCD。
- 所有配置共用角色冷却缓存。`BAG_UPDATE_COOLDOWN` 记录客户端实际冷却；物品使用请求后，只有背包数量/次数确实减少才使用核对过的数据保留最后一件物品消耗后的冷却。使用错误会取消待确认请求，不会仅凭点击启动倒计时。此内存记录在重新加载界面后重建，重新持有物品时以客户端数据重新读取。
- 不做自动地面施放，不通过宏调用恢复品或炸药。短效 Buff 可显式启用宏，`macroWarningSeconds = 0` 避免效果尚未结束时反复消耗。
- 回归测试：`tests/consumable-cooldowns.lua` 覆盖新增设置项、ID 匹配、共享类别、真实短 CD、GCD、工兵自身 CD、最后一件消耗、失败使用、魂能自施放和宏默认行为。

### 武器强化与毒药执行及监控

- `addon.IsWeaponCategory(category)` 是武器类物品的统一判断入口；设置布局、全选、旧选择迁移、小窗、右键和补药宏均通过它识别“武器强化”和“毒药”。毒药选择同样存入每配置的 `weaponSlots`，无需单独数据库结构。
- 毒药附魔通常按武器提示中的毒药类型识别，与本地 Cat/EzPoison 方式一致；致命毒药因同时收录 IV/V，必须按等级精确区分，确保倒计时和剩余次数不会串到另一等级。以后增加其他同类型等级时也必须细分等级匹配。

- 主手槽位固定为 `16`，副手固定为 `17`。小窗为每个已启用槽位生成独立条目，不能再按物品名合并两手时间。
- `weaponEnchantCache` 按槽位保存 `{ itemName, expiration, charges }`；`GetWeaponEnchantTime(itemName, slot)` 和 `GetWeaponEnchantCharges(itemName, slot)` 必须同时匹配物品和槽位。
- 次数读取复用 CatLib 主副手计数的武器提示“数字＋次”解析方式，缺少提示次数时使用 `GetWeaponEnchantInfo()` 的正数次数作为后备；无法读取时保存 nil，不虚构 0。仅在小窗有可见毒药条目时每秒合并重扫双手附魔，确保攻击消耗次数也能更新；隐藏后停止周期扫描，重新打开立即刷新。
- 点击武器强化条目时，`UseItem(itemName, itemData, weaponSlot)` 先使用背包物品，再调用 `PickupInventoryItem(weaponSlot)` 落到目标手，并处理中文“替换”确认框，最后清理光标。
- 对应手没有装备物品时必须提前阻止使用并显示“主手无武器”或“副手无武器”。
- 点击后在约 `0.2` 秒和 `1` 秒补扫武器附魔缓存，以适配旧客户端背包消耗与附魔状态不同步。
- 小窗可见且检测到进食时，每秒重读 Buff 时间；检测到进食结束后再每秒补扫两次，随后恢复缓存倒计时，以覆盖同名烹饪 Buff 续期未触发事件或延迟到达的情况。

## 关键设计约定

1. `addon.Categories` 与 `addon.SettingsOrderItems` 同时控制设置列表、小窗和 `/catpotion` 的顺序。
2. 所有 139 个物品都有 `addon.ItemTextures` 静态纹理。旧客户端的 `GetItemInfo` 缓存不稳定，不要改回动态取图标。
3. Buff 通常按名称识别；魔血药水与夜鳞鱼汤因为 Buff 同名，刻意使用 `buffIcon` 区分。
4. 状态文字优先级是：效果倒计时、物品冷却、点击使用、背包无物品。鼠标提示先显示效果，再显示冷却。
5. 背包、Buff 和武器附魔采用事件标脏与延迟合并扫描；不要改成逐帧全量扫描。
6. `/catpotion` 和原生热键共用 `CatPotionUseCommand()` 并固定使用默认配置；带配置名的命令使用指定配置，每次硬件按键最多尝试一个物品。
7. 施法、引导或“正在进食中”时，一键补药不会触发，以免打断或重复消耗食物。
8. `UseContainerItem` 在该客户端没有可靠的成功返回值，因此插件只能提示“尝试使用”，不能即时声称服务器已确认生效。
9. 武器附魔缓存按装备槽位 `16`（主手）和 `17`（副手）独立保存，同一种强化可同时监控两只手。
10. 小型样式或文字调整不要自动增加版本号；仅在用户明确要求时修改 `Core.lua` 和 TOC 中的版本。
11. 每套药剂配置保存普通物品勾选项、武器强化的主/副手选择及缩放、排列方向、每行或列项目数；锁定小窗位置、聊天栏提示和剩余时间警告也在配置管理中按配置保存；已有配置继承旧全局值，新配置默认不锁定、开启聊天提示、提前 4 分钟警告。小窗显示状态和位置也按配置保存；“窗口归位”只处理当前配置。旧单小窗的开关和位置仅迁移给原当前配置，其余配置默认关闭。删除配置会关闭对应小窗。多个窗口共享一个定时/事件刷新器及背包、Buff、武器附魔缓存。
12. 药剂冲突关系集中维护在 `Core.lua` 的 `addon.ItemConflictPairs`；设置界面只读取它显示提示，使用逻辑不得据此做互斥或跳过。
13. 设置操作不得在鼠标回调中同步重排可见的 `CatPotionWindow`；`RefreshPotionWindow()` 只登记请求，由独立驱动器在下一帧内原子执行“隐藏、重排、恢复”。最终状态会在该帧渲染前恢复显示，兼顾旧客户端安全与无闪烁体验。
14. `CatPotionWindow` 禁止启用原生 `SetClampedToScreen(true)`：WoW build 5875 在边缘拖动时会触发 ERROR #132。也禁止在 `OnDragStop` 中调用 `GetLeft/GetRight/GetTop/GetBottom` 后立即 `SetPoint` 做软边界，实机确认同样会在边缘崩溃。拖动结束只能保存客户端当前锚点；意外出屏使用“窗口归位”。

### 2026-08-21 药剂窗边缘崩溃记录

- 症状：拖动 `CatPotionWindow` 接近屏幕边缘时，游戏不是普通 Lua 报错，而是客户端直接退出。崩溃日志为 ERROR #132 / ACCESS_VIOLATION，相关内存中出现 `DBG:CatPotionWindow`。
- 已失败方案 A：`SetClampedToScreen(true)`。原生夹紧在 WoW build 5875 上会触发崩溃，必须永久保持 `false`。
- 已失败方案 B：关闭原生夹紧，在 `OnDragStop` 读取窗口四边并立即用 `SetPoint` 纠正越界。实机仍会在边缘崩溃，禁止再次采用。
- 已失败方案 C：松手后转换锚点并在下一帧自动回拉。没有解决交互问题，窗口会弹回原位置，禁止再次采用。
- 当前安全基线：`OnDragStop` 先 `StopMovingOrSizing()`，然后只通过 `GetPoint()` 保存当前锚点和偏移；不读四边、不做坐标换算、不调用位置刷新。允许窗口被拖出屏幕，并由“窗口归位”按钮恢复。
- 后续若要重新研究贴边，必须保留当前安全基线，并在 build 5875 客户端中单独实测；代码层面的静态推断不足以证明安全。

## 当前界面基准

- 设置窗口：`780×620`。
- 设置列表：普通物品三列、图标 `18×18`、名称字体 `12`、纵向步进 `25`；武器强化两列、图标 `20×20`、纵向步进 `28`，共用独立滚动区域。
- 药剂小窗：不使用滚动条，根据已选数量、排列方向和每行或列数量自动扩展。
- 药剂小窗背景为半透明，每项宽 `135`、高 `40`，效果倒计时优先于冷却时间。

## 修改后的检查流程

毒药次数的模拟回归测试位于 `tests/weapon-charges.lua`，可在工作区根目录运行 `fengari CatPotion/tests/weapon-charges.lua`。测试覆盖主副手隔离、次数后备读取、过期清空、图标角标和可见窗口的周期刷新；不能代替游戏内视觉与实际涂毒测试。

1. 使用旧版 Lua 语法解析器检查所有 `.lua` 文件。
2. 检查 `Bindings.xml` 能被 XML 解析，并确认 TOC 中列出的文件全部存在。
3. 如果项目根目录存在 `Sync-CatPlugins.bat`，运行 `Sync-CatPlugins.bat --no-pause` 同步到默认游戏目录。
4. 其他机器若带有该脚本，可运行 `Sync-CatPlugins.bat "目标游戏\\Interface\\AddOns" --no-pause` 指定目标目录；否则直接复制插件目录。
5. 比较工作目录与游戏目录的文件哈希，然后在游戏中执行 `/reload`。

现有同步批处理（如果随工作区提供）会同时复制 `CatMeleePrompt` 和 `CatPotion`，不生成 ZIP。
