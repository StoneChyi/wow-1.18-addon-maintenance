## 后续同步

用户已于 2026-10-09 持续授权：今后每项插件修改及其修改说明都必须在维护完成后同步到本私有仓库，无需逐次询问是否上传；单独补充或修订修改说明也同样提交并同步。

1. 按 `AGENTS.md` 完成插件修改和适用检查，同时更新对应 `PluginHistory/Plugins/插件名.md`；必要时同步总索引与待补充清单。将本次负责的插件文件和说明明确纳入提交，不遗漏新增依赖、资源和必要的删除。
2. 核对仓库状态与远端目标，审查本次提交。使用 Python 执行 `Tools/audit_github_upload.py`，检查所有可达历史中的常见令牌和私钥模式、排除目录及 GitHub 文件大小限制；不能保证发现所有敏感数据。
3. 维护完成后主动运行 `git push origin main` 同步已提交的插件和说明，并确认远端分支包含本次提交；不要仅完成本地提交就结束。新建的标签应审查后明确指定推送；不要强制推送或覆盖已有基线。
4. 如果远端存在本地没有的提交，先检查并整合，再推送。存在未提交改动时不要为了同步而覆盖或撤销它们；其他任务的未审查内容不得夹带。
5. 网络、登录失效或远端冲突导致失败时，保留本地提交，明确报告未同步的提交及原因，恢复条件后再正常推送；不能声称已上传。

仓库保存全部现用插件及依赖，避免遗漏早期自定义改动。`WTF`、账号/角色设置、`Imports` 登录资料、日志、缓存、游戏数据和截图仍排除在代码仓库之外。第三方插件保留原有版权与许可。
