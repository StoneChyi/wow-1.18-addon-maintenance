## 后续同步

根据 2026-10-09 的持续同步要求和 2026-10-24 的公开上传授权，今后每项插件修改及其修改说明都必须在维护完成后同步到本公开仓库，无需逐次询问是否上传；单独补充或修订修改说明也同样提交并同步。

1. 按 `AGENTS.md` 和[记录规范](记录规范.md)完成插件修改及适用检查，在对应 `PluginHistory/Plugins/插件名.md` 新增独立条目。运行 `Tools/plugin_history.py build`、`check` 和 `Tools/check_plugin_notes.py`；必要时维护证据状态与待补充清单。用 `checkpoint --note 明确路径` 或明确审查后的暂存方式，将本次负责的插件文件、说明和变化的索引一起提交，不遗漏新增依赖、资源和必要的删除。自身提交号通过该页 Git 历史关联。
2. 核对远端目标为上述仓库及其可见性，审查本次提交；公开状态已获持续授权。使用 Python 执行 `Tools/audit_github_upload.py`，检查所有可达历史中的常见令牌和私钥模式、排除目录及 GitHub 文件大小限制；不能保证发现所有敏感数据。
3. 维护完成后主动运行 `git push origin main` 同步已提交的插件和说明，并确认远端分支包含本次提交；不要仅完成本地提交就结束。新建的标签应审查后明确指定推送；不要强制推送或覆盖已有基线。
4. 如果远端存在本地没有的提交，先检查并整合，再推送。存在未提交改动时不要为了同步而覆盖或撤销它们；其他任务的未审查内容不得夹带。
5. 网络、登录失效或远端冲突导致失败时，保留本地提交，明确报告未同步的提交及原因，恢复条件后再正常推送；不能声称已上传。

仓库保存全部现用插件及依赖，避免遗漏早期自定义改动。`WTF`、账号/角色设置、`Imports` 登录资料、日志、缓存、游戏数据和截图仍排除在代码仓库之外。第三方插件保留原有版权与许可。
