## 正式服 Decursive 的逻辑与界面

Decursive 根据角色已掌握的驱散能力配置操作，按队伍成员建立 Micro Unit Frames（MUF，小方块）。传统界面用亮起的小方块提示需要处理的人，鼠标按钮对应驱散法术，悬停显示详细信息。旁边的 Live List 列出需要处理的目标与减益。名单可以调整优先级或跳过队员；大小、间距和排列方向可配置。这里的“一键”是玩家点击后施法。

参考：[作者的 MUF 文档](https://www.wowace.com/projects/decursive/pages/main/mufs)、[项目介绍与界面图库](https://www.curseforge.com/wow/addons/decursive)、[作者提供的经典游戏界面截图](https://media.forgecdn.net/attachments/106/544/Decursive_Afflcited-1.jpg)。截图用于说明传统布局，不代表当前 12.1 版本的所有功能都可用。

源码中，队伍模块组织成员并处理优先/跳过名单；技能变化事件安排重新配置。参考：[队伍模块](https://github.com/2072/Decursive/blob/master/Dcr_Raid.lua)、[事件模块](https://github.com/2072/Decursive/blob/master/Dcr_Events.lua)。

截至本次检索，项目主页列出的正式服版本为 2.9.0-RC3（2026-10-04）。需要区分传统功能与当前正式服限制：作者的 12.1 兼容说明明确提到，距离变暗、减益过滤、普通减益 Live List、视线失败黑名单等受到接口限制。因此本次参考的是 Decursive 的成员提示与能力识别思路，结合乌龟服的 1.12 接口自行实现，并非直接搬运正式服源码。参考：[12.1 兼容说明](https://www.curseforge.com/wow/addons/decursive/files/8821707)。

## 原 hyx 的具体问题

- 点击法术写死为“清洁术”，没有按职业和已学技能选择。
- 扫描只接受魔法、中毒和疾病，遗漏诅咒。
- 超过 `maxInRange` / `maxOutRange` 的目标未保存到可浏览列表，后面的目标无法查看。
- 直接调用 UnitXP；接口未加载或调用异常时会中断更新。
- 优先/黑名单原来只放在临时全局表中，重载后会重建为空。

## 已实现的职业支持

以实际技能书为准，不会把未学习的技能当成可用技能。

| 职业 | 友方驱散类型 | 识别的技能 |
|---|---|---|
| 骑士 | 魔法、毒、疾病 | 清洁术；未学时纯净术负责毒/疾病 |
| 牧师 | 魔法、疾病 | 驱散魔法、祛病术/驱除疾病 |
| 德鲁伊 | 诅咒、毒 | 解除诅咒、驱毒术/消毒术 |
| 法师 | 诅咒 | 解除次级诅咒 |
| 萨满 | 毒、疾病 | 消毒术、祛病术 |
| 术士 | 魔法 | 当前宠物技能书中的吞噬魔法 |
| 战士、盗贼、猎人 | 无匹配的常规友方驱散技能 | 正常加载，保持列表为空 |

支持简体、繁体和英文技能名。乌龟服新增或改名的特殊技能，如不在上表中，仍需根据实际技能书另加规则；“全职业识别”不等于凭空给予每个职业驱散能力。本版范围为友方减益，未增加敌方增益驱散、消耗品驱散、心控解救或全团宠物作为被驱散目标的扫描。

## 列表操作

- 两列保留完整目标集合，超过显示行数后用滚轮逐行浏览。
- 两列分别保存滚动位置；锚点锁定后，行上和列表空隙仍可滚动。
- Shift + 滚轮向上回到首行，向下跳到末页。
- 超过一页时显示位置，例如 `6-10/23 滚轮浏览`。
- 左键/右键对当前行驱散；中键选中队员；悬停查看减益和所用法术。
- 保留“自己 → 优先名单 → 其他成员”的排序、黑名单、自定义屏蔽和团本手册设置。
- 保留每列 3–10 行的设置。列表更新时尽量维持滚动位置对应的人。
- 锚点拖动位置、优先名单和黑名单写入原来的 `xinDB`。

每 0.25 秒更新一次。实际长冷却、距离过远、视野之外、未知距离及可检测到的法力不足会进入不可驱散列。短公共冷却不会使整列来回跳动，便于连续点击和客户端的技能排队。

点击时重新检查名字、存活/连接状态、友方关系、黑名单、减益、过滤规则、技能和可用条件。原减益已经消失或队伍编号换人时，该次点击不施法。

## 现有 DLL 如何参与

- `UnitXP_SP3.dll`：使用 `distanceBetween`、`inSight`。术士从宠物位置判断，其他职业从玩家位置判断。调用有异常保护；失败时不把未知距离误标成可驱散。
- `SuperWoWhook.dll`：检测 `SUPERWOW_VERSION` 后使用 `CastSpellByName(法术名, 单位)`，保留当前目标。
- `nampower.dll`：可用时使用其 `IsSpellInRange`、`IsSpellUsable` 接口。宠物距离采用 UnitXP 来源位置，避免套用玩家位置的结果。
- SuperWoW 未加载时走旧客户端选中目标、施法、还原目标的兼容路径。

本地 Rinse 和 SuperCleveRoidMacros 的代码提供了这些接口的使用依据。DLL 文件存在不代表已成功加载；`/xin status` 可显示插件实际看到的接口与技能。本次未替换或修改任何 DLL，也未引入 CoreBridge 新调用。

## 使用与验证

1. 输入 `/reload`（或 `/console reloadui`）重新载入界面。
2. 输入 `/xin` 或原命令 `/xinload` 打开设置；`/hyx` 也可打开。
3. 输入 `/xin status` 查看识别到的驱散技能。
4. 在队伍中出现超过显示行数的可驱散目标后，把鼠标放在列表上滚动。
5. `/xin top` 将两列都回到首行。

离线测试通过 14 组行为检查，使用 Lua 5.1 与模拟的 WoW 1.12 界面/API。覆盖完整插件加载、九职业技能识别、宠物切换、最高等级技能、40 人目标集合、滚动边界、名单过滤、距离/视野/冷却/法力、DLL 缺失或抛错、过期行点击保护、目标还原及设置保存。测试文件：`E:\1.18\addons_tmp\test_hyx_dispel.py`。

尚未在登录的游戏客户端中实测。需要在游戏中确认中文字体下的行宽、滚轮事件、当前 DLL 版本的定向施法，以及术士宠物的施法表现。视线检测结果不是服务端施法成功保证；最终抵抗、法术失败和具体战斗机制仍由游戏判定。

沿用原有“单一屏蔽”的含义：忽略该减益的提示并寻找其他减益；法术本身可能同时移除多类减益，无法保证只移除当前显示的一项。需要整个人暂不驱散时，使用原来的“完全屏蔽”。
