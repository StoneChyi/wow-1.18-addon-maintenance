# DPSMateX 精确统计扩展

新增独立的“治疗与实际吸收”“成功施放”“动作回放”模式，使用 DPSMateX 的窗口、菜单与详情风格，不需要启用 ShaguDPS。原治疗、吸收、施法模式继续保留。

## 使用

新增插件目录后，请完全退出并重新启动游戏，在插件列表确认启用 **DPSMateXInsights**（依赖 DPSMateX）。首次安装会将三个新模式加入启用列表，后续尊重 DPSMateX 的模块开关。

- 右键 DPSMateX 标题栏选择新模式。
- 左键玩家条目进入详情；治疗详情左键技能查看右侧数值，右键技能或点击“目标”查看目标分布。
- 左键总计查看团队总览；右键玩家的“对比”沿用原入口，打开第二个详情窗口。
- “动作回放”使用当前或历史单场战斗，选择该模式时会将全程视图切换到当前战斗。
- 详情支持名称搜索、来源分类；治疗与实际吸收使用滚轮/滚动条，施放和回放使用分页；回放还支持目标类型和时间区间筛选。
- 治疗详情使用与原伤害/治疗详情一致的880×450三栏布局：左侧饼图，中间带图标的技能/目标列表，右侧命中、暴击和吸收表（次数、占比、平均、最小/最大值）。保留总治疗/有效治疗口径切换、搜索、来源筛选、目标类型筛选和核对记录；不展示HPS或时间曲线。
- 技能明细按名称合并不同等级、技能 ID 及来源；来源筛选仍可分开查看，点入目标明细会汇总对应记录。悬停显示合并的技能 ID。动作回放继续逐次显示真实事件。
- 技能、Buff、Debuff 使用技能记录对应的图标 ID，按需读取并缓存；普通攻击与死亡使用独立图标。详情不提供跨模块切换按钮。

命令：

| 命令 | 功能 |
| --- | --- |
| `/dpsx` | 打开治疗与实际吸收详情 |
| `/dpsx raw` | 在有效治疗＋吸收与总治疗＋吸收之间切换 |
| `/dpsx status` | 显示运行时 Nampower 版本、吸收总量/来源未知/排除量、回放保留/丢弃数量 |
| `/dpsx debug` | 切换限量调试日志，最多保存最近200条 |

## 统计口径

- 吸收采用伤害事件中的实际金额，按受保护者的护盾生命周期及伤害学校判断来源。不使用固定护盾容量截断事件金额。
- 只有一个适用护盾时归给该护盾施法者；多个适用护盾属于同一施法者时保留施法者，技能显示“多重护盾（技能未知）”；多人来源冲突、缺少护盾记录或无法确认施法者时计入“来源未知”。
- 统计包括自身护盾和可识别的物品/药水吸收；红月、蓝月单独排除。不能证明具体护盾归属的金额不会任意分配。
- 实际吸收总量 = 已归属吸收 + 来源未知吸收 + 排除吸收。“来源未知”单独展示，便于核对，不归到任意治疗者。
- 命中与暴击按 Nampower 治疗事件的 critical 标记分类；吸收独立列出。总治疗口径显示原始数值，有效治疗口径显示缺血限定后的数值；旧记录没有分类标记，会归入“未分类”，不会猜测暴击。分类只保存固定数量的累计值和极值，没有恢复逐秒曲线采样。
- 治疗量单独记录；有效治疗按收到治疗事件时的目标缺血计算。无法取得血量时按总治疗记录，并在核对日志标记 `health-unavailable`；有效治疗的精度仍受事件和血量更新时序影响。
- 成功施放仅按 SPELL_GO 计数，群体技能、多段伤害和持续治疗跳数不会增加施放次数。事件包含玩家、宠物及物品触发，不等同于只统计手动按键。
- 回放记录成功施放、普通/副手攻击及相关死亡事件；死亡标记不增加动作次数。回放是事件时间轴。

## 保存与调试

数据单独保存到每个角色的 `DPSMateXInsightsDB`，历史与 DPSMateX 分段同步保存、删除和重置。旧战斗显示“该战斗未采集”，不补造旧数据。统计汇总和历史不共享可变表。

限制：每人保留最近500条回放，全场最多8000条；详情显示实际保留/丢弃数，丢弃回放不会减少成功施放、动作次数或治疗汇总。旧回放会自动按新上限缩减，保留最近的事件和统计汇总。治疗不再采集逐秒贡献曲线，旧的曲线采样在加载时一次性释放，累计金额保留。每场保留最近300条核对记录。历史场数跟随 DPSMateX 配置。

资源控制：无关事件、已关闭模块会提前退出；技能名称及图标缓存最多512项，单位身份缓存最多256项。死亡事件通过保留回放的目标索引查询，不逐次扫描所有动作。详情仅在打开、滚动、翻页或操作时整理数据和读取图标；空闲时停止定时整理。治疗饼图最多12个主要项目加“其他”，选中技能或滚动时分布未变便复用饼图。窗口和行控件复用，未增加每帧刷新。调试默认关闭，已有调试设置会保留。新增模块不扫描整个技能表、不周期扫描全队 Buff/Debuff。

“核对”页显示金额、时间、施法者、目标、技能及归属依据；悬停查看 GUID 和技能 ID。开启调试后，可在角色的 SavedVariables 中查看 `DPSMateXInsightsDB.debugLog`。不能解析的施法者会短暂等待名字，最多2秒；超时记为未解析，回放页显示数量。

重载/重新进入世界后不会凭旧缓存猜测仍在生效的护盾归属；在看到新的护盾应用前，相关吸收可能进入“来源未知”。插件只能记录客户端收到的事件，缺失事件不能从历史补出。Nampower 不足4.5或缺少必要API时，新模块提示无法采集。

## 本次验证

根目录 `Logs/nampower_debug.log` 和上一份日志记录加载 Nampower **4.6.1**。扩展运行时也通过 `GetNampowerVersion()` 检查能力。

30项扩展模拟/语法检查通过，覆盖护盾学校、刷新/移除/死亡、重叠护盾与未知金额守恒、群体治疗施放计数、宠物及物品、分段/重载、记录上限和详情交互；另通过原窗口锁定回归检查。还核验了同名技能合并及目标明细、图标 ID 转换与缓存、死亡目标索引、旧回放容量迁移、核心事件转发时的参数保存、旧版 Nampower 的停用行为、紧凑面板的空数据和布局边界、饼图容量与复用、选中数值刷新以及旧曲线采样清理。尚未在游戏内核验真实事件顺序、画面和战斗性能；离线检查不能保证游戏中完全没有资源开销。

本机 Lua 5.1 模拟压力检查：10万条无关事件约0.006秒；模块关闭后1万条施法事件没有单位API查询；回放饱和后继续处理4万条施法约0.372秒，回收后的保留内存增量为0 KiB，5万次施法的汇总仍为5万。模拟40人共24000条动作时，保留8000条、丢弃16000条、动作汇总24000次。这里使用模拟API，不代表魔兽客户端的实际耗时或帧率。
