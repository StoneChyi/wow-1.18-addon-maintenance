# 插件修改记录规范

自 2026-10-15 起使用本格式。每个维护过的插件保留一个 `PluginHistory/Plugins/插件名.md`，每次修改单独记录，最新记录在前。文件名使用实际插件目录名。

[插件修改记录](Plugins/README.md) · [记录模板](记录模板.md) · [待确认插件](待确认插件.md)

## 插件文件

1. **插件概况**：名称、维护状态，以及整理日期与实际修改日期的区别。
2. **当前维护摘要**：简短说明当前实际保留的行为。方案被替代时更新摘要，原记录保留。
3. **逐次修改记录**：每次修改、更新合并、测试反馈、来源补充、方案或停用各占一条，按日期和当日编号倒序。
4. **早期历史汇总与维护依据**：无法准确拆分的旧修改、原始说明、关联插件、待补充项和证据链接。旧记录中的“当前”“本次”属于当时语境。

只确认关联皮肤适配的插件单列；尚未确认个人修改的插件保留原页，列入待确认索引。来源信息不等于个人修改，不能将整合包现有功能都写成本项目新增。

## 每次记录的内容

按[模板](记录模板.md)写清日期、标题、记录编号、类型、游戏验收状态及对应提交；正文记录修改原因、具体变化、涉及文件、关联功能、真实检查结果、未确认事项和必要的替代关系。

- 编号采用 `插件名-YYYYMMDD-01`。同日继续递增，不重用或重排旧编号；新增记录置于更早记录之前。
- 标题采用 `### YYYY-MM-DD｜标题`，前放独立的 `<a id="change-记录编号"></a>`，为索引提供稳定链接。
- 类型可选：修改、更新合并、实测反馈、方案、来源补充、差异核对、停用、范围确认。正文必须说明方案是否实施。
- 游戏验收可选：`待游戏验收`、`用户实测（限本条范围）`、`不适用（说明或停用记录）`。实际结果及范围写在正文；通过一项不代表整个插件已通过。
- 检查结果写明实际执行的检查、环境和结果。模拟通过与游戏验收分别记录；未执行的检查不能沿用旧结果冒充本次结果。
- 对应提交填写已存在的完整提交链接。代码和新记录同次提交时填写 `随本条记录一并提交（见本页 Git 历史）`，提交后通过本页 Git 历史查找，无需追加提交来填写自身哈希。
- 用户补充、验收或更正按实际确认日期新增条目，并引用原记录编号。撤回或替代方案也新增记录；仅纠正笔误时可直接修订，Git 保留修订过程。
- 同次维护涉及多个插件，在各插件页分别记录各自变化，并引用同一个维护提交及关联页面。不要把所有变化只写在一个插件里。

无法确认原修改日期的内容留在早期汇总。以后取得证据时可以补录，分别写明真实修改日期、依据和补录日期，不补造历史提交时间。

## 索引和证据

`Plugins/README.md`、`待确认插件.md`、`change-index.json` 由 `Tools/plugin_history.py` 从插件记录和现有维护清单生成，避免手工维护多份日期、标题和条数。先编辑插件页；新增插件或证据状态变化时同时维护 `maintenance-index.json`，再生成索引。

`maintenance-index.json` 继续保存证据状态、主要文件、来源和历史参考关系。`addons` 与 `counts` 对应原参考目录集合；初始化后新增插件使用 `added_addons` 与 `added_counts`，不混入历史 105 项。统计和状态只随真实依据变化。

`addon-catalog.json`、`baseline-files.json`、`history-index.json` 和 `Evidence` 保留原始含义；本次整理不改写这些历史证据。整合包研究和原始检查报告继续保留，通过插件记录链接引用。

## 每项维护的流程

1. 检查工作区、暂存区和近期提交，明确本次负责的范围。
2. 修改插件并完成适用检查；保留文件原编码、BOM 和换行。
3. 在对应插件页新增条目，更新当前摘要；必要时维护证据状态、新插件清单和关联插件页。
4. 运行下列索引生成和文档检查，再审查差异、新增文件及删除文件。

```text
python Tools/plugin_history.py build
python Tools/plugin_history.py check
python Tools/check_plugin_notes.py
```

5. 将本次负责的代码、资源、记录和生成索引放入同一次提交。`checkpoint --note` 可重复指定明确审查过的说明、研究报告及索引，不会自动收取整个记录目录。例如：

```text
python Tools/plugin_git.py checkpoint --addon YGB_OTAlarm --note PluginHistory/Plugins/YGB_OTAlarm.md --note PluginHistory/Plugins/README.md --note PluginHistory/change-index.json --message "YGB_OTAlarm：说明修改目的；验证：填写实际结果"
```

若本次还修改 `maintenance-index.json`、待确认索引或研究报告，也必须明确加入。暂存区非空时工具仍拒绝操作；插件自带仓库仍按实际文件记录，不生成 gitlink。工具或其他不在该参数范围内的文件需另行明确审查和暂存，不得使用无范围的 `git add .`。

6. 核对已授权的私有远端，运行 `Tools/audit_github_upload.py`，正常推送并确认远端包含本次提交。审计不能保证发现所有敏感信息。失败则保留本地提交，明确未同步的提交及原因；不强制推送。
