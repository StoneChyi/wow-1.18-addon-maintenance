# EavesDrop 1.12 优化与验收说明

实施日期：2026-10-26；收尾复核：2026-10-27。本次基于当前个人使用版实施；没有完整旧官方原包，不追溯归属此前修改。没有替换 DLL、写入账号配置、执行 DLL 或启动游戏。

## 已实施行为

- 主框架默认隐藏；Ace2 初始化读取停用标记后不会再露出空框。运行中停用同时清理两类数据监听与刷新任务、隐藏主窗和最高值历史。`/ed` 和 `/eavesdrop` 在停用时仍可打开设置；`enable`、`disable`、`legacy` 子命令分别启用、停用、进入旧高级设置。
- 所有旧文字战斗渠道共用一个分发回调；补充队友/友方直接治疗、宠物及其他相关渠道，过滤与玩家/自己的宠物无关的事件。宠物选项仅控制过滤，不再注销玩家治疗/资源共用渠道。修正宠物承伤、输出治疗统计方向与颜色；增强 GUID 标志优先于宠物名称匹配。
- 配置刷新和重复启用前清理或重建对应订阅，避免经验/声望/荣誉等重复。关闭自动隐藏后恢复窗口 alpha，阅读状态下重新启用仍可见。玩家 GUID 初次不可用时等待进入世界后重试；停用时不重试。
- 滚轮离开底部时复制一份有限历史，后续实时记录独立继续收集，当前阅读内容与提示文本不被循环复用的表改写；阅读时停止淡出。底部提示新增条数，点击或滚回底部恢复实时跟随。缓存默认 512 条，可在 128–2048 间调整；调整容量时保留最新记录并结束阅读副本。阅读副本即使已从实时缓存淘汰也暂时保留，退出阅读时释放。该缓存仅保留本次登录；最高数值历史继续使用原单角色存档。
- 新增独立分页设置，覆盖外观、事件、颜色、历史与数据、配置。主/历史窗口背景不透明度共用 `FRAME.a`，设置面板使用 `SETTINGALPHA`；0% 为透明，100% 为不透明，滑块即时预览。仅调整背景，不改变文字/按钮的整体 alpha。使用本机 pfUI 的有效接口与字体，缺失或加载失败时保留独立细框样式和内置字体。
- 保留现有位置、大小、颜色、过滤设置、最高值历史和旧高级设置入口；没有改动其他插件的 Dewdrop、Waterfall 或全局字体。旧版过量治疗仍是基于即时血量的估算，没有新增服务器精确过量字段，不将其宣传为精确数据。

## 增强记录与来源边界

新增 `enhanced.lua` 适配本机固定留存的 nampower 4.6.1 参考事件协议。参考源码不代表现用 DLL 可逐字节重建；运行时仍检查真实 `GetNampowerVersion`、GUID 与事件能力。

| 类别 | 使用方式与保留边界 |
|---|---|
| 法术伤害 | 处理增强直接/周期伤害、暴击、吸收/格挡/抵抗；百分比 DoT 原值单位不确定时按技能回退文字，不将百分数当生命值 |
| 普攻 | 处理命中、暴击、偏斜、碾压、未命中及减免字段 |
| 法术未命中 | 使用实际未命中原因，玩家/宠物身份由 GUID 过滤 |
| 治疗 | 仅订阅 BY_SELF/BY_OTHER，不额外订阅 ON_SELF，避免自疗重复 |
| 资源恢复 | 按 powerType 映射本地化资源，保留健康资源的独立类型 |
| 伤害护盾 | 保留文字日志；增强事件先后顺序不足以保证首次去重，不伪造护盾 spellId |
| 环境伤害 | 保留旧文字解析中的摔落、溺水、熔岩等；增强事件先后顺序不足以保证首次去重 |
| 光环 | 保留文字日志；对象光环变化与文字事件没有可靠先后关系，暂不启用增强替代，不将层数变化冒充消失 |
| 吸取、汲取、击杀归属 | 保留旧文字日志；不以无来源的 UNIT_DIED 冒充玩家击杀 |

4.5 以下保留全部旧日志；单类别注册失败仅该类回退。来源切换不按时间/数值相似度去重，避免误吞同一时间的合法多段命中。缺失法术身份时使用明确的未知名称，不伪造具体技能。增强提示文本显式传入显示和最高值历史，不读取增强事件中含义不同的全局 `arg1` 充当原文。

事件订阅、实际收到数据、服务器提供哪些数据属于不同事实。只有收到相关玩家/宠物的有效增强事件后才激活该类旧来源抑制；没有收到时继续使用文字。来源状态分别报告已订阅和已收到类别。保留增强的五类已核对为先发增强再调用原文字处理；`auras.cpp`、`unit.cpp` 的光环、护盾和环境路径没有同等顺序保证，因此保持文字来源，避免第一次双记。

本机参考源码的 RegisterEvent 会启用 DLL 内部发射开关，但不更新 GetCVar 保存值。因此不能把 CVar 初值为 0 当作注册后仍关闭。为覆盖其他设置插件运行中再次关闭（包括同值 0）事件，适配器仅观察三个相关 SetCVar 调用，原样调用原函数、保留 1.12 三参和全部返回值，不自行写入任何 CVar；关闭时恢复文字来源，重开后等待有效增强事件。停用时若观察函数仍位于最外层则撤回，若另有插件 hook 则保留惰性链，避免切断其他插件。另检查 GetCVar 的相对值变化。若代码绕过当前 Lua 入口且使用同值关闭，公开 API 不能查询内部开关，仍属未覆盖边界。

离线模拟不能证明当前服务器每个场景的增强包都完整；没有部署新的 DLL。

## 游戏验收步骤

1. `/reload` 后右键窗口或 `/ed`，分别调整主/历史和设置面板背景至 0%、中间值、100%，确认文字/按钮清晰；拖动、锁定、滚轮和历史窗口操作正常。
2. 停用后依次验证 `/reload`、退回角色选择、完全退出重进、切换配置；窗口不出现、两路监视不再追加记录，仍可通过命令进入设置重新启用。另验从淡出状态关闭自动隐藏后重启/切配置可见。
3. 队友直接治疗、自疗、持续治疗、普攻、直伤/DoT、暴击、格挡/吸收/抵抗、PvP、资源恢复分别比较原生战斗文字与 EavesDrop；自疗只出现一次。核对新技能名称与图标，缺失信息应使用明确后备。
4. 宠物出战后检查输出/承伤/受疗，反复开关宠物监视，玩家治疗与资源恢复持续正常；同名其他宠物不得混入增强身份。
5. 向上滚动持续阅读，再让新事件超过实时缓存容量；原阅读副本不移动或淡出，提示新增数。点击底部或滚到底恢复实时。分别验 128、512、2048 容量与少于一屏的情况。
6. 核对增强来源状态，在旧日志模式、无增强能力、运行中关闭增强事件等场景确认回退；旧文字光环叠层/减层/消失分别验证。实际服务器未提供的字段不承诺可补齐。

用户实测后应按实际确认日期追加独立记录，不改写本条为已通过游戏验收。
