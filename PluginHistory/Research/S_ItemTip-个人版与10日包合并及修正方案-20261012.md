当前观察文件还重复定义了 `ItemSocre:TranslatedItem`，运行时由后一个定义生效。衔接时应保持这个实际生效版本的翻译优先级；不要为了删除重复代码意外换回前一个版本。是否单独清理死代码不属于本次必要合并。

## 1. 名称冲突：统一按需查询，不保留两套策略

拟在 `ItemSocre.lua` 提供共用解析入口，逻辑结果分为：精确 ID、唯一候选、多个候选、暂时未找到。返回状态必须分开，不能统一用 false 表示。

解析顺序：

1. 调用方已有物品链接或 ID 时，优先使用该 ID 查询物品资料和装等；直接 ID 已命中时，完全不进入名称扫描。
2. ID 查不到、确需名称回查时，先查本次会话已请求名称的候选缓存。首次请求该名称才遍历英文库，收集全部同名候选，而不是遇到一个就返回。
3. 只有一个可用候选时可以回查。多个候选时，可利用已有且已加载的品质、装备类型等资料缩小范围；资料缺失不能当作不匹配。
4. 仍有歧义时不任意选择首个、末个或最高装等。链接查询返回未解析；评分保留现有可算部分，标记结果不完整，不写入普通完整结果缓存。若候选的装等完全相同，可仅复用确定的装等数值，不能因此伪造唯一物品 ID/链接。
5. 观察框能通过真实 ID 获得名称时继续使用真实 ID；歧义时保留原显示名称，不用另一件同名物品替换翻译或附魔上下文。

英文库没有对应名字时，链接查询再考虑客户端已知物品资料；中文名称不能强行当作英文库索引。评分、AtlasLoot、链接和观察框最终调用同一个候选解析入口，移除新旧独立名称索引。

建议名称请求缓存最多保留 512 个名称，达到上限清理最久未使用项；只保存已请求名称及其候选，不保存整库反向索引。上限是待测试初值，不能据此宣称没有额外内存或首次扫描开销。

## 2. 评分缓存：避免旧值、别名遗漏和刷新顺序依赖

拟保留 `ItemSocre:ScanUnit(unit)` 的首个返回值和通常调用方式，增加可选的强制重扫参数；内部另有完整性状态。旧调用方不必修改即可读取分数。

| 情况 | 拟处理 |
| --- | --- |
| 同一单位连续悬停/重复查询 | 完整结果缓存 0.5 秒；非强制调用可复用。 |
| 物品链接存在，但品质/类型等资料尚未加载 | 视为暂时不完整；不得把未加载当成确定空装备。最多用 0.1 秒短期结果限制重复查询，并安排有限次刷新。 |
| 确定没有装备 | 与资料未加载区分；确认已就绪的空结果可以按正常 TTL 缓存。无法确认时保守按不完整处理。 |
| `UNIT_INVENTORY_CHANGED` | 清空整张短期评分缓存，覆盖 player/target/mouseover 等别名；在各个负责显示的回调内，先失效，再重算。 |
| 观察开始/观察对象切换 | 清除相关评分及待处理显示任务，使用实际传入的单位，避免硬编码 target。 |
| 观察资料确已就绪 | 在已确认可用的通知路径清缓存，再强制刷新；不能只等待 TTL。 |
| 目标或队伍成员变化 | 在本客户端确认存在的目标/队伍变化事件中清评分缓存，防止单位标识复用。 |
| 进入世界、数据源变更、手动重置 | 统一清缓存和待刷新任务。 |

每个缓存项附带统一的数据代数；任何来源失效时递增代数，旧结果不能命中。缓存项过期后回收，限制最多 128 项，避免不断悬停新玩家导致表无限增长；上限为初值。

不依赖“评分框事件一定先于 StatCompare 事件执行”。StatCompare 的装备事件处理、观察框关键刷新路径均先主动调用统一失效入口，再读取评分。即使清理回调反向执行，也不能把旧缓存显示后就不再更新。

`S_ItemTip_UpdateFrame(unit, force)` 的普通调用继续使用 0.08 秒节流；关键换装/数据就绪调用可跳过这一次节流。附魔包装函数同步透传 `force`，继续尊重基础函数的 false 返回值，防止装备更新被节流但附魔图标单独重画。

若资料未齐，安排 0.2、0.5、1 秒至多 3 次重试；每次只在对应窗口仍显示同一对象时执行。之后停止自动重试，后续真实通知或用户再次查询仍可触发，不能进入永久轮询。

现有文件注册了 `INSPECT_READY`，这不证明实际 1.12 客户端一定发该事件。实施时核对本机使用的观察数据通知路径，并保留上述有界重试作为补充；不新增对现代 `UnitGUID`、计时器或物品资料事件的无条件依赖。

## 3. 链接缓存：允许恢复，限制首次慢查询

新包永久失败缓存已复现不恢复。本次建议采用以下规则：

- 无名称/空名称立即返回，不建查询任务。
- 有真实链接或 ID，直接验证使用；拍卖浏览优先评估本机已有 `GetAuctionItemLink(type, index)` 路径，按 1.12 实际接口验证后接入。邮箱不假定存在现代附件链接接口。
- 成功缓存存 ID 或基础链接，不缓存被本地化、附魔等上下文加工过的提示行；使用时重新取得必要资料。缓存跟随数据代数，建议最多 256 项。
- 失败记录有效期 1 秒，期满允许重试；物品资料未就绪、英文库未就绪、真正没有候选、名称歧义分别记录。失败不写入永久缺失列表。
- 所有拼链接分支先验证名称、超链接和品质；不能只有名字就连接字符串。关键资料缺失走“暂时未就绪”，避免 nil 拼接错误。
- 英文候选也无法提供链接时，旧范围 1–25818 的客户端资料扫描改成独立工作帧分批执行，初拟每帧全局最多 256 次 `GetItemInfo`，最多 8 个不同名称任务；同名请求合并。达到任务上限时返回待重试，不强行同步扫完。
- 扫描总范围初版保持旧上限；已知精确 ID 或英文库候选可超过该范围。不能宣称分批扫描解决了高 ID 中文物品的覆盖问题；扩展范围需另行依据和测试。
- 查询完成后，仅在提示仍显示同一物品且对象仍有效时更新；鼠标已移动则不把旧结果写入新提示。任务结束卸载工作帧 OnUpdate，不覆盖其他插件已有的提示脚本。

分批查询意味着第一次显示可能短暂缺少附加装等，取得链接后再补；应在验收中明确检查这项行为。新包同步扫描的卡顿不能靠“改成失败不缓存、然后每次重扫 25,818 个 ID”来解决。

## 4. 数据源变化：让所有缓存一起失效

拟提供统一的 `ItemSocre:InvalidateCaches(reason)`，并为旧调用点保留必要适配。名称缓存检测英文库表身份；评分同时检测装等库表身份。来源被替换或有明确重载通知时，递增数据代数并清名称、链接、评分和相关显示任务。

同一张表内部原地修改，单靠表身份无法察觉。只有库提供修订号时才能按修订号检测；否则在已知的数据重载入口显式失效，并提供本地手动重置入口。不能承诺自动检测任何第三方任意原地改表。

原 10 日全量索引清理接口不保留为一张必须先构建的完整映射。新包全目录核对未发现外部调用，不需为了兼容不存在的调用构建索引；如实施时发现新的外部使用方，再明确做接口适配并列入验证。

## 5. 负充能和钩子：保持个人修复

背包、拍卖浏览、拍卖出售继续保留原条件：计数为负且存在对应 SuperWoW 能力标志时才转正。普通正数和零保持，缺值不报错；不对所有负数无条件取绝对值，不改变 ItemCount.lua 的现有统计口径。

原钩子必须保持原参数、调用次数与返回值，尤其观察、拍卖、AtlasLoot 和 pfUI 的调用链。`InspectUnit(unit)` 当前旧逻辑硬编码扫描 target，10 日包也沿用；这是既有问题，计划改为实际参数并等待资料就绪后更新，避免观察非目标单位时错算。此项是兼容修正，不冒充 10 日新增回退。

本次不新增界面控件。若为提示行更新而触及 FontString，仍须验证首次 SetText 前已有有效字体，保留内置后备，并在模拟中覆盖 SetFont 失败；不得以空字体模拟代替真实前置条件。

1. 在独立 staging 目录保存个人版候选与三份源文件校验值；实施前重新检查 Git 和 S_ItemTip 源文件，避免覆盖其他任务。保存明确负责的提交和更新前标签后再开始代码维护。其他任务尚有未提交改动时，不把它们夹带进提交；先协调到明确基线或使用独立工作目录，标签不代表未提交内容也已保存。
2. 迁入类型集合、提示助手、固定权重，验证评分规则和原钩子行为不变。
3. 实现共用按需候选查询，替换评分/AtlasLoot/观察翻译实际调用；处理同名歧义和数据源失效，解决文本冲突。
4. 实现链接缓存及分批回退，再接入人物评分缓存、关键事件和强制刷新；保留全部个人界面与充能逻辑。
5. 完成下表的受控检查，审查完整差异、编码/BOM/换行和新增文件；按负责文件更新维护说明、本地提交并审查后同步私有仓库。候选替换现用目录前须有可回退记录。
6. 真实客户端验收分别记录。未实际测试的阶段明确标为待验收；发现错评分、误链接或布局回退时回退本插件候选，不回退其他任务。
