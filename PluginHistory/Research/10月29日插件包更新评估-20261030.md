## 先修正再采用的具体问题

1. **新资源条的法力文字缺少字体后备。** `energybar.lua` 的主文字有 `GameFontNormalSmall` 模板，附加法力文字却无模板，只尝试配置字体。执行实际创建/样式函数，并使用仓库严格 FontString 模拟：正常字体可写文字；配置字体失败时附加法力文字的 `SetText` 报 `Font not set`。合并前应加入有效模板和内置字体后备，覆盖开关、复用及失败路径。
2. **新底部对齐没有完整转换 TOP/CENTER 锚点。** 执行实际 `PlayerBottom`：UIParent 高 1080、玩家框高 40，TOPLEFT 偏移 -100 时应得到底边 940，实际返回 -140；CENTER 偏移 0 时应得 520，实际返回 -20。默认 BOTTOM/300 返回 300 正常。采用自动布局前需处理锚点原点与缩放，并保留已有手动位置。
3. **新天赋应用器按标志类型猜测前置参数长度。** 既有同文件逻辑按 `(tier,column,flag)` 三元组读取；新函数只在 flag 为 boolean 时前进 3，否则前进 2。执行实际新函数，两项前置的 boolean 模拟正确返回 `[1,2]`，数字 1 模拟错为 `[1,1,3]`，nil 模拟只得到 `[1]`。实际客户端返回类型未读取，采用前应固定正确签名并验证 0.4 秒等待、0.25 秒重试和失败跳过恢复，暂不整文件更新 SpecialTalent。
4. **ATSW 的词法问题是继承项。** Lua 5.1 拒绝新包第 4063 行的 `1then`；旧包和当前版第 3979 行存在完全相同的语句。它不属于本次新增故障，且本次没有用 Lua 5.0 判定其真实客户端表现。临时副本只补分隔空白后，新包可通过 Lua 5.1 编译及 32 upvalue 检查；未修现用代码。
5. **GoubayuHeal 原始 UI 的局部变量上限仍未修。** 新旧包均在第 6254 行被 Lua 5.1 拒绝，个人版通过。此次新包只改驱散姓名颜色，不应借更新之名覆盖个人 UI 修复。

以上模拟仅说明给定输入下实际代码的行为；没有把模拟的 API 类型、字体失败或几何条件说成已在游戏中发生。

## 检查结果与建议顺序

变更/新增的 106 个 Lua 文件中，105 个通过 Lua 5.1 编译，所有成功编译文件的嵌套闭包均未超过 32 upvalue；唯一未通过项为上述 ATSW 继承语句。新旧包 TOC/XML 各有 21 项既有缺失引用，没有新增缺失；此检查包括包内 TOC 的递归文件引用，客户端自带文件另列，不把它们当作插件缺失。

本机已有 Lua 5.0 编译程序本次因 Windows 错误 623 无法启动，因此本次未完成真实 Lua 5.0 编译。未启动游戏、未验证渲染性能、战斗事件、团队通信或配置迁移，也没有执行候选 DLL。包内注释的性能数字与“实测”属于来源陈述，不作为本机测量结果。
