# EavesDrop：装备触发、临时召唤与手动采样

日期：2026-10-27（北京时间）。[插件维护页](../Plugins/EavesDrop.md#change-EavesDrop-20261027-04)。

## 已实施的功能

新增“触发与召唤”和“事件采样”设置页，沿用 pfUI 风格与设置面板的背景、边框不透明度。`/ed procs`、`/ed capture` 可直接打开对应页。默认启用装备提示和临时召唤监视；诊断采样默认关闭，重新启用插件或重载也不会自动开始采样。

首批规则为“失落之物／迷失者”，依据现有本地 DPSMateX 的 Babble-Spell-2.3 中文表中精确技能名“召唤迷失者”、pfQuest-turtle 的中英文单位名及 NPC 59993；没有猜测召唤技能 ID 或英文技能名。保留 `RegisterProcRule` 供后续增加有证据的规则。

- **召唤触发提示**：默认订阅 `COMBAT_TEXT_UPDATE` 的 `SPELL_CAST`，仅匹配已核实名称；表示收到施法提示，不证明单位已生成。
- **技能可用提示**：`SPELL_ACTIVE` 单独记录，不累计到触发次数。不能把反应技能变为可用解释为召唤成功。
- **首次发现**：增强战斗事件中首次确认属于自己的迷失者，显示“首次发现：迷失者”。它表示首次被本插件观测，不是精确生成时间。
- **召唤战斗记录**：对已知 NPC/名称并有主人证据的单位，记录伤害、受伤、治疗和未命中。普通宠物槽仍由原宠物逻辑处理；临时召唤开关独立于普通宠物开关。

触发提示来源可手动切换为 nampower `SPELL_GO_SELF` 或 SuperWoW `UNIT_CASTEVENT`，一次只使用一种施法来源计数；不支持所选来源时显示不可用，不静默改用别的来源。原始采样可同时收集多来源用于比对，采样条数不等于触发次数。nampower 触发技能的 itemId 可能为 0，不能因此丢弃，也不能仅靠 itemId 证明装备归属。

归属优先读取当前 owner，再读取有版本约束的 `summonedBy`／`createdBy`；明确属于他人时立即排除。每次战斗重新检查归属，不把名称或旧缓存当作证明。仅对 `0xF130` 生物 GUID 解码 NPC entry，不对玩家/物品套用生物编码。增强事件涉及玩家时保留原伤害/治疗通路及最高值统计，独立记录仍可查询，避免在主窗双显。

“并入战斗事件窗口”可关闭；关闭后记录仍在“查看最近触发记录”中。该窗口最近优先、每页 16 条、悬停显示来源，手动刷新。记录最多 128 条，已见 GUID 缓存最多 256 个，本次登录的计数与记录在配置切换、插件停用/重启用时保留，重载后不保留。首见缓存淘汰后再次观测可能再次提示，不能将首见计数当作准确生成数量。

## 实测步骤

1. `/reload` 加载新模块。确认插件监视已启用；保留能让默认浮动战斗信息显示该提示的游戏设置。
2. 输入 `/ed capture`，点击“开始新一轮事件采样”。**新一轮会替换旧采样**。
3. 穿戴失落之物套装，触发迷失者，让它攻击数次。留意默认浮动文字和 EavesDrop 的提示、首次发现、伤害是否对应。
4. 点击“停止并保留采样”。正常 `/reload` 或退出游戏，使本轮写入本机 EavesDrop 设置存档。告知已完成采样后，可在本机分析，不需要公开上传账号设置。
5. 如出现新问题，保留本轮，先分析再开始下一轮；也可用 `/ed capture status` 查看状态。

也支持 `/ed capture start`、`stop`、`clear`。采样最多 120 秒或 1000 条，达到任一上限自动停止；停用监视和退出游戏也会停止并保留。手动清除只清除本模块的采样，不重置插件配置或最高值历史。

## 采样内容及界限

`EavesDropCaptureDB` 独立保存一轮有界诊断数据：相对时间、白名单事件、最多九个原始标量参数、已知单位 GUID/名称/归属、可解析技能名及 ID。单个字符串最多 384 字节并避免截断 UTF-8 字符；不序列化表或非有限数字。

仅订阅战斗相关白名单，不订阅私聊、频道聊天或登录资料；旧文字限定本人/宠物和疑似迷失者记录，增强记录限定玩家、宠物、本人召唤物或已知迷失者候选。归属未知和他人归属会明确标注，候选不等于本人召唤物。默认浮动信息按原始 1.12 `arg1/arg2` 参数记录，不调用现代战斗文本接口。

每轮同时保存开始时的扩展版本、所选数据/触发来源、四个白名单 CVar 的只读值、实际注册与不可用事件清单，便于重载后分析。当时环境只代表采样开始时的状态。没有主动写 CVar、启用文件战斗日志、自动上传、自动学习规则或部署 DLL。

## 已知限制与后续判定

- 默认浮动提示是否实际投递，以及套装在本服究竟发送 `SPELL_CAST`、`SPELL_ACTIVE` 还是其他提示，仍需上述真实采样确认；默认 UI 可显示某文字不能证明插件已经捕获到对应事件。
- 目前没有实测核实召唤 spell ID。若实际名称不同、无施法事件或只出现技能可用提示，先依据采样补充精确规则，不凭时间接近推定召唤成功。
- 临时召唤战斗监视需要相关增强事件实际投递且 NPC 与主人对象可读取。纯旧文字模式或归属缺失时不强行计入本人伤害；状态栏会提示限制。
- 新模块目前不归属资源恢复、光环、吸收盾及百分比 DoT 的文字回退；增强事件与客户端看不到的单位仍可能漏记。没有实现准确生成/消失时间、存活时长或服务器级完整召唤计数。
- 本次采样模块跨重载保存，正常监视记录仅本次登录保留。采样限制、缓存上限和未开始采样均可能影响证据完整性。
