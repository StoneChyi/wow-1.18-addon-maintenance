# TianYan：无姓名板召唤物发现重构

日期：2026-10-28。维护页：[TianYan](../Plugins/TianYan.md#change-TianYan-20261028-01)。

## 原因与证据

用户关闭友方姓名板，迷失者仅在鼠标指向后被统计。原代码只自动监听 UNIT_COMBAT_GUID、UNIT_MODEL_CHANGED_GUID、UNIT_DIED；定期扫描不能枚举没有姓名板、目标或鼠标令牌的未知单位。

用户授权的 2026-10-27 本机采样中有 66 条涉及本人迷失者的观测，来自 UNIT_CASTEVENT、SPELL_GO_OTHER、SPELL_DAMAGE_EVENT_OTHER、AUTO_ATTACK_OTHER，包含三个不同单位，主人信息可读。旧版不监听这些发现入口。以同一匿名事件样例回放，旧版始终为零，新版识别三个单位。采样没有记录原版所订阅的全部事件，不能证明旧事件完全未投递，也不能锁定哪次 DLL 更新改变了行为。

原始采样及账号数据仅在本机；仓库内样例只含重新生成的 GUID、相对时间、公开事件名、参数和匿名归属，不含账号、角色名或真实 GUID。

## 实现

- 新增 Tracker.lua，分离识别/缓存与 UI、统计。TOC 先加载 Tracker，再加载 TianYan；版本为 2.1.0。
- 接入采样中确认的施法与攻击事件，按各事件真实参数位置读取单位 GUID。施法 START 也可作为“该生物已被观察”的入口，但必须继续核对实际单位、主人及存活状态。玩家召唤提示不直接增加数量。
- 归属优先读取 owner；接口版本支持时补充 summonedBy、createdBy，再用严格的提示行回退。明确属于他人立即拒绝，暂时缺少信息与拒绝分开处理。
- 新单位或归属信息尚未齐全时，加入最多 64 项、每项最多两秒的重试队列，扫描周期约 0.3 秒。不会无限缓存失败单位。
- GUID 去重；临时姓名板转 GUID 时替换旧记录。有 GUID 但查询未就绪时仍允许已确认归属的姓名板估计；同 GUID 多板不重复计数。
- 确认死亡立即清理并阻止短暂旧状态重新计数；失去观察的记录短暂估计，界面继续用 ~ 标注。仍可确认存活的单位不会因没有姓名板或超过三十秒而过期。
- 事件时刻立即更新数量乘时间积分与历史最高；正常 UI 刷新由周期扫描完成，避免每个战斗事件全量扫描界面。
- 保留当前数、分类数、时间加权均值、历史最高、重载保存、清空历史按钮和 220 宽界面。修正小地图拖动使用不存在的 LockPoint 及固定按钮中心计算角度的问题。
- 不再尝试设置旧客户端不保证存在的友方姓名板 CVar，也不改写全局 GUID 事件开关。
- /tydebug 增加本插件版本、Nampower 自报版本、各入口注册/实际接收次数、发现与重试计数，便于游戏验收。注册成功不代表事件已实际投递。

## 验证

Tools/tests/test_tianyan.py：30 项测试通过，包括完整插件在严格字体模拟下加载、SetFont 失败保留模板、隐藏窗口、清空历史与已保存均值、无扩展/注册失败回退、无鼠标无姓名板的各发现入口、主人字段与他人归属、重试上限/超时、同名与多入口去重、临时姓名板升级、消失估计与死亡、部分战斗、零时长、小地图拖动、66 条实际采样匿名回放。另含 20 组共 600 次生成/死亡事件与独立存活时间计算对照。

用独立 Lua 5.0 编译器检查实际 Tracker.lua、TianYan.lua 通过。原有文件 UTF-8 无 BOM、CRLF 保留；新增 Tracker.lua 采用相同格式。TOC 加载顺序和文档检查另行执行。

## 游戏验收与限制

以上是离线检查，没有操作游戏角色或确认游戏实际表现。需重载后在关闭友方姓名板、不选中、不指向迷失者时触发，并观察首次施法、攻击、死亡和消失。
