## 修正的风险与实际策略

- 保留背包、拍卖浏览、拍卖出售三条负充能归一化；仅在原 SuperWoW 条件下处理负数，普通客户端不无条件取绝对值。
- 名称、链接、评分缓存分别上限 512/256/128 项；按最近使用时间淘汰，不分配整库反向索引。按需名称首次查询仍会遍历英文库，本次没有声称首次查询零开销。
- 收集同名候选；品质/装备类型能明确排除时缩小范围，资料尚未加载时不据此排除。多个候选装等一致时可复用数值，仍不生成假定唯一的物品链接；不同装等且无法消歧时保持未解析，不把另一件装备冒充当前物品。
- 链接缓存成功保存 ID，取用时验证必要资料；失败不永久缓存。英文候选已知但资料未齐时有限重试；未知名称的客户端资料扫描共享每帧 256 次预算，最多 8 个并行名称任务，按名合并请求。
- 异步补提示前检查窗口显示、所有者、原提示标题及当前邮箱/拍卖上下文；其他提示入口取消旧请求，防止结果写到新物品上。
- 装备、单位/队伍变化清短期评分；StatCompare、观察框显示回调主动先失效再读取，不依赖回调先后顺序。换装也刷新当前可见的自有单位装等提示。
- 资料未齐时于 0.2/0.5/1 秒最多 3 次自动重试；窗口隐藏或对象变化会取消。工作完成后卸载 OnUpdate，不保留永久轮询。
- 检测英文库和装等库源表身份变化，清理相关缓存。无修订通知的原地修改仍需 `/si cacheclear`。
- 新写入文字的路径有字体初始化保护；没有模板且两个后备 SetFont 都失败时，停止写文字。原有面板模板在显式 SetFont 失败时仍有有效字体，模拟中保留 FontString 未初始化则 SetText 必须失败的约束。

## 验证

[受控行为检查](../../Tools/tests/test_s_itemtip_merge.py)在候选目录和部署后的现用目录均通过 **85 项**：

- 三份改变文件通过 Lua 5.1 语法编译。
- 覆盖各品质、猎人/非猎人、双手/单手、副手/远程的 48 个公式样本；完整资料下保持原规则。
- 缓存命中/到期/强制重扫、源表替换、手动重置、别名失效和回调顺序颠倒。
- 唯一/歧义名称、相同装等重复 ID、精确 ID、品质与类型消歧、资料未齐后恢复。
- 链接首次失败后恢复、缺品质、全局分帧预算、任务结束停止、同名任务合并与错误提示取消。
- 三条充能路径在有/无能力标志、nil/负数/零/正数下的行为；拍卖精确链接优先；钩子参数与含 nil 的多返回值。
- 严格 FontString 前置条件、SetFont 失败、无模板且字体后备失败；面板首次/重复打开和开关、自动/自由模式、强制穿过节流。
- 加载实际 EnchantAPI 和附魔包装代码，验证图标准备、复用、隐藏，以及 false 返回协议；自用和他人面板在换装/资料通知后的更新。

这些检查使用受控 API 和界面对象，并非真实客户端画面或游戏验收。原始编码、BOM 保留，混合换行文件仅在实际改动区域写入新行，没有全局转换换行。原始与部署文件的 SHA-256、85 项结果见[实施校验依据](S_ItemTip-合并实施-20261012.json)。
