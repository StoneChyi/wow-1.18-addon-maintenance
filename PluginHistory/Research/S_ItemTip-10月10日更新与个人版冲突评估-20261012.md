## 文本冲突在哪里

以旧包为共同文件对照运行 `git merge-file --diff3`，返回 **1 个冲突块**，位于 `ScanUnit` 在直接 ID 查不到装等后的名称回查分支。

当前个人版调用：

```lua
local realID = GetScoreItemIDByName(itemName)
if realID then itemLevel = LibItem_Level[realID] or 0 end
```

10 月 10 日包调用：

```lua
local realID = S_ItemTip_GetEngNameToItemID()[itemName]
if realID then
    itemLevel = LibItem_Level[realID] or 0
end
```

两者目标相同，但策略不同：个人版按名称逐个缓存，首次请求每个新名称可能扫描英文库，额外内存随已请求名称增加；新包第一次需要时扫描整库，保存所有名称，后续新名称直接查表，但首次分配和常驻索引更大。本机当前英文库实读为 24,893 个 ID、23,940 个不同名称。

仅删冲突标记不足以完成合并：若保留个人 `ScanUnit` 分支，但让 AtlasLoot 和链接查询继续调用新包全量索引，会同时留下两套名称缓存，也不能完整保留“避免首开面板全量建索引”的个人维护意图。应先确定统一策略，再处理全部调用点及清理逻辑。

## 不会报文本冲突、但需要处理的风险

| 风险 | 检查结果 | 实际影响与建议 |
| --- | --- | --- |
| 3 处负充能修正被删除 | 原始代码在模拟输入 `-5` 且存在 `SetAutoloot` 时，旧包/个人版三条路径均输出 `5`；新包均输出 `-5` | **确认行为回退。** 保留现有归一化。此检查只证明提示字段值，未据此声称游戏内总价或具体 UI 已错误。 |
| 链接失败缓存没有过期 | 首次 `GetItemInfo` 无数据，随后让数据可用：旧包/个人版下一次可获得链接，新包仍返回 nil；显式清缓存后恢复 | **确认缓存恢复缺口。** 短期未加载被记为长期不存在，影响按名查链接入口，如邮箱/拍卖提示。建议失败不永久缓存，采用短时重试或明确的数据就绪失效路径。 |
| 同一人的多个单位标识分别缓存 | 先扫描 `target` 得 4.8，换装后只发 `player` 事件；新包 `player` 得 6.4，`target` 仍为 4.8 | **确认此输入下旧值可保留至 0.5 秒到期。** 事件是否按此顺序实际到达，需游戏验证。建议事件时清整个短期评分缓存，或统一身份与全部别名失效。 |
| 全量索引不会检测英文库源表替换 | 首次名字指向 60 装等物品，替换源表使其指向 80 装等物品，超过评分 TTL 再查：个人版 4.8→6.4，新包仍 4.8 | **确认动态源表场景差异。** 不代表游戏一定会替换该表。建议保留个人版源表身份检测，并与所有结果缓存一起失效。 |
| 同名物品的取值规则变了 | 当前英文库有 562 个重名名称，其中 204 个名称对应不同装等；旧包/个人按需查询取遍历遇到的第一个，新包整表赋值保留最后一个 | **确认碰撞及策略变化，具体装备受影响尚未确认。** 如 `Signet of Expertise` 有 45/65 两种装等。直接 ID 命中者不走此分支；不得只凭同名认为同一装备，建议优先精确 ID、明确同名消歧。旧策略也不保证唯一正确。 |
| 整包覆盖观察面板 | 新包两个观察文件与旧包相同；当前个人版已有明显改造 | 覆盖会失去 StatCompare 自动/自由排列、层级/背景策略、拖动定位、文本宽度缓存、刷新节流及显示前附魔图标准备。新评分接口签名仍为 `ScanUnit(unit)`，未发现必须覆盖这些文件的接口理由。 |

装备变化时，评分清理回调和 StatCompare 更新回调的真实执行顺序，以及观察资料就绪后应否额外清缓存，尚未做真实 1.12 客户端验证；不能把“注册了装备事件”视为所有刷新路径都已解决。

## 建议的合并范围

1. 以当前个人版为基础，只人工迁入 `ItemSocre.lua` 的必要增量；原样保留当前 `InspectFrame.lua`、`InspectGemAndEnchant.lua`，不替换未更新的数据库与贴图。
2. 可采用装备类型集合、共用装等提示助手、文件级固定权重；评分公式保持现状。
3. 评分短缓存有收益，但接入前补全换装、观察数据更新及单位别名的失效逻辑；验证 StatCompare 和观察框刷新没有读到旧值。
4. 统一名称查询策略，优先保持个人版避免首开全量索引的意图；若需要整库索引，则明确接受其分配开销并补源表失效、同名消歧。不保留两套互不协调的索引。
5. 链接缓存可以加入，失败必须有重试；3 处负充能归一化继续保留。

本次未生成宣称可用的合并版，更没有替换现用插件。合并后仍需用真实客户端验收首开/重复打开角色框、观察他人、换装、鼠标悬停、AtlasLoot、邮箱/拍卖和带充能物品，并检查 BetterCharacterStats、StatCompare 的联动。
