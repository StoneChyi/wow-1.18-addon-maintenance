# 插件本地 Git 记录

本仓库从 2026-10-08 开始建立。`main` 保存当前个人使用版，完整覆盖现有 105 个插件目录，以及根目录 DLL 与相关加载配置。所有记录仅保存在本地。

## 已有修改如何纳入

初始化及补全提交保存当前使用版的完整文件，而不是重置插件。完整基线标签：`baseline/current-2026-10-08`。`baseline-files.json` 保存初始化时每个现用插件文件的长度和 SHA-256。没有完整干净原整合包，因此该标签不能称为官方原版。`baseline/bootstrap-2026-10-08` 仅留存最初初始化检查点，尚未补全自带仓库插件的实际文件，恢复时应使用完整基线标签。

历史归档提交整理已有修改前备份、补丁、说明和验证记录。`history-index.json` 记录归档文件的来源、长度和 SHA-256；`addon-catalog.json` 记录现用插件和能找到的历史依据。未发现修改证据不代表没有修改，所以全部插件都保存当前基线。初始化期间新增的 HideOutdoorWorldState 插件已先产生独立维护提交，该提交完整保留。

历史备份在 `Evidence`：

- `legacy-20261006`：已有整理包中的逐文件修改前快照、差异、文档和清单，包含早期 18 个插件的依据。这些是不同阶段的备份，部分已含更早修改；必须阅读其中的来源和覆盖限制。
- `addons_tmp`、`CodexBackups`、`CatBackups`：本项目中后续维护的源码备份、补丁、说明和测试脚本。归档仅用于审查，未经重新核对不可直接运行旧部署脚本。
- `reports`：现有维护报告，以及 DLL 原版/候选文件等依据。候选 DLL 仅归档，不代表已安装。
- `nested-repositories`：3 个插件原有独立仓库的历史导出。原有仓库保持原位，主仓库另存其实际文件，避免只保存无法独立恢复的子仓库引用。`.git` 内部数据不混入插件文件清单。

归档保留原有文件，未修改现用插件，没有把中间备份拼成虚构的官方版本，也没有补造历史提交时间。账号设置、导入登录资料、日志和测试依赖不归档。

## 后续维护

每项修改完成后按插件或关联功能提交，说明修改目的和检查结果。`AGENTS.md` 已写入后续自动记录要求。Git 记录需要执行提交，不会自动监视或阻止第三方更新器覆盖文件。

可使用 Python 运行维护工具（系统 Python 不可用时使用 Codex 自带 Python）：

```text
python Tools/plugin_git.py status
python Tools/plugin_git.py verify
python Tools/plugin_git.py checkpoint --addon CatPotion --message "CatPotion：说明修改目的；验证：填写实际结果"
python Tools/plugin_git.py checkpoint --addon DPSMateX --addon DPSMateXInsights --message "DPSMateX：关联功能调整；验证：填写实际结果"
```

`verify` 会逐字节检查提交中所有文件，并检查插件目录有无未记录文件；与历史标签比较时会列出正常的后续变更。`checkpoint` 只记录指定插件，暂存区非空时停止，避免混入其他任务的内容。维护文档和工具变更应另行审查并明确提交。

## 下次更新整合包

1. 保存当前改动并打更新前标签，将新包解压到独立暂存目录。
2. 有经过核实的旧原包时，用旧原包、当前个人版、新原包做三方比较与合并。只有真实原包才建立 `upstream` 历史。
3. 没有旧原包时，依据归档和文件差异人工迁移，标明无法确认的内容，不盲目覆盖。
4. 审查同文件冲突、二进制替换、删除以及配套依赖，在独立目录完成合并，再替换现用插件并检查游戏行为。

Git 可以恢复已提交的插件文件，不能代替账号配置备份。`WTF` 另行备份；本地仓库也建议定期复制到另一磁盘，或在维护暂停时用 `git bundle create` 导出所有分支与标签。当前未设置远程地址，也未上传任何内容。

插件自带的 `.gitattributes` 可能要求转换换行。主仓库的 `.git/info/attributes` 使用 `* -text -filter -ident` 作为最高优先级保护，原有规则文件保持原样。复制整个仓库时保留 `.git`；从导出的历史重建仓库时，需要先恢复该本地规则再检出插件文件。
